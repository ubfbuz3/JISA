## 0. 术语

| 符号 | 含义 |
|---|---|
| `alarm` | 判定器把该实例**升级为 `violation-proven`**（唯一计为"报告了一个漏洞"的裁决） |
| `indeterminate` | 判定器**弃权**（明确不作判定） |
| `pass` | MR 未触发，无需裁决 |
| `bola` | 真值：该 (主体, 对象) 上应用**实际允许**了**本不该允许**的访问 |
| `normal` | 真值：应用行为正确（允许合法访问，或拒绝了越权访问） |

---

## 1. 混淆矩阵语义（必须先定义再比较，否则数字不可对齐）

```
truth = bola,   alarm = true   → TP
truth = bola,   alarm = false  → FN
truth = normal, alarm = true   → FP        ★ 本文称「假确证」
truth = normal, alarm = false  → TN
```

**为什么 `alarm` 定义为"升级为 violation-proven"而不是"MR 触发"：**
MR 触发只表示**输入间的变形关系被违反**，它是**证据**不是**结论**。
本文关心的是"测试工具最终向开发者报告了什么"，故以**最终裁决**为准。
这一区分是本文的核心：**触发 → 裁决**这一步正是失效发生的地方。

> 与之配套的两个量：`raw_false_alarm`（原始误报，即未修正的告警落在 `normal` 上）与
> `false_proof`（`raw_false_alarm` **且**最终裁决为 `violation-proven`）。
> `false_proof ⊆ raw_false_alarm`。

---

## 2. 假确证率（本文引入的指标）

$$
\text{FPR}_{\text{proof}} \;=\; \frac{\#\{\text{alarm} = \texttt{violation-proven} \;\wedge\; \text{truth} = \texttt{normal}\}}{\#\{\text{原始误报}\}}
$$

**为什么不能只看这个指标，也不能不看它：**

- 它衡量"**当你本已出错时，出错的方式有多危险**"。带 `violation-proven` 标签的错误会被开发者当作已确证的漏洞处理，
  与"可疑但未确证"的误报**后果不同**。
- 但它的分母是**原始误报**，故**不反映检测能力**。单独报它会得到一个"既高又无意义"的数。
- ⇒ **必须与召回、F1、弃权率并列报**。

**分层要求（强制）**：`introspection = on` 与 `off` 两个子集的假确证率**必须分别列出**。
合并会掩盖两种制度：`on` 时 v3 因 oracle 可读而消除假确证（0.00）但保住检测（1.00）；
`off` 时 v3 因无法排除不透明授权而**全部弃权**（假确证 0.00 但检测力 **0.00**）。
**把两者合并会把"诚实弃权"读成"性能优异"。**

## 3. 弃权率与检测力保持率

$$
\text{AbstainRate} = \frac{\#\{\text{verdict} = \texttt{indeterminate} \text{ 且原因 = oracle 不可读}\}}{\#\{\text{实例}\}}
\qquad
\text{KeepRate} = \frac{\#\{\text{alarm} \wedge \text{truth}=\texttt{bola}\}}{\#\{\text{truth}=\texttt{bola} \wedge \text{MR 触发}\}}
$$

- `KeepRate` 的**分母**限定为"真越权 **且** MR 触发"，因为它衡量的是"修正是否**误伤**了本已成功的判定"。
  把未触发的真越权算进分母会把它与召回混淆。
- `AbstainRate` 的分子**只计因 oracle 不可读而弃权**，不含"因 MR 未触发而 pass"。

**地板值（必须并列报）**：`degrade_all`（凡触发即弃权）给出 `KeepRate = 0.00` 且 `FPR_proof = 0.00`。
**任何修正机制只有在 `KeepRate > 0` 的意义上才优于"一律弃权"**，否则它只是把弃权伪装成裁决。

## 4. specificity 口径复现与其分辨率问题

MST-wi 报告 specificity **99.81%**；MST/Mai19 报告 **99.50%**（32/6401 FP）。

$$
\text{specificity} = 1 - \frac{\#\{\text{false alarms}\}}{\#\{\text{follow-up inputs}\}}
$$

**本文的复现（近似）**：以"每 case 2 条 follow-up input"近似分母，三个配置分别得到
`numbers.tex` 中 `\ResSpecRow*Spec` 的取值。

> ⚠️ **这不是原引擎的精确输入计数**，只用于说明该口径的问题：**分母是"输入数"而不是"场景数"**。
> 一个场景即使**整类失效**（例如全部带外授权场景都误报），只要该场景贡献的输入数在总量中占比小，
> specificity 仍会停在 99%+。⇒ **该口径在结构上低分辨率于场景级失效**。
> 这是本文的**度量口径注记**，不是"MST-wi 报错了"。原文的 FP 归因是**异步动作**，
> 与本文讨论的对象级授权**不是同一个成因**。

## 5. 不确定性报告规则（强制）

1. **所有比例**给 Wilson score 区间（95%），实现见 `compute_all.py::wilson`（无需 scipy）。
2. **方法间差异**给 Newcombe 混合评分区间（`rd_ci`）。
3. **差异不显著时必须明写**。当前实例：
   `direct_observe` 与 `v3` 的召回差 ΔR = **0.0139**，95% CI **[−0.0797, +0.1072]** ⇒ **含 0，不显著**。
   ⇒ 结论只能是"**点估计不劣于**"，**不是"严格支配"**。
4. **样本量必须披露**：合成矩阵 n = 576（其中 bola 216、normal 360）；真实系统 96 单元格。
   ⚠️ 但**必须同时披露有效独立单元**（见 §9）：n = 576 是**设计组合数**，不是独立重复数。
5. **不得只报点估计**；不得用"显著"修饰未经区间的比较。
6. **区间必须标注为"约定性"**：本设计是固定矩阵的确定性枚举，Wilson/Newcombe 假设的独立伯努利抽样**不成立**，
   故区间**系统性偏窄**。正文首次出现区间处必须写明这一点。

## 9. 有效独立单元与区间解读（统计审查结论）

> 依据 `nature-statistics` skill 的 audit（完整报告见 `STATISTICS_AUDIT.md`）。

**设计结构（由 `compute_all.py::design_structure` 从原始记录重算）**：

| 量 | 值 |
|---|---|
| 记录数 | `\ResSynRecords` = 576 |
| **独立设计格** | `\ResDesignCells` = **52** |
| 每格记录数 | `\ResDesignMinPerCell`–`\ResDesignMaxPerCell` = 6–12 |
| **MR 条数** | `\ResDesignMrs` = **2**（MR-002、MR-004） |
| 情景数 | `\ResDesignScenarios` = 7 |
| 格内展开 | `\ResDesignCellExpansion` = 6 = `precond_variant`(3) × `gui_mode`(2) |

**为什么这决定了一切**：

- `precond_variant`（raw / e1 / e1e2）与 `gui_mode`（blind / aware）是**被刻意拨动的确定性开关**，不是重复实验。
  同一格内 12 条记录共享对象图、`setup` 与真值。
- ⇒ **记录之间不独立**。把 576 当 576 次伯努利抽样是**伪重复**（pseudoreplication），
  会让区间**系统性偏窄**。
- ⇒ 正文每条计数**同时给设计格数**；区间只用于**量级与方向**，**不用于跨方法显著性主张**。
- ⇒ **有效重复层级**：设计格 52 / MR **2** / 情景 7 / 真实系统 1。
  对"MST-wi 的 MR 总体"的外推上界就是 **MR 条数 = 2** —— 这是本文最硬的一条限制（见 §6）。

**唯一例外及其稳健方向**：Block 9 的 `direct_observe − v3` 召回差 Newcombe 区间
（`\ResAbRecallDiff`，CI `[\ResAbRecallDiffLo, \ResAbRecallDiffHi]`）同样偏窄；
但**偏窄只会让差异更容易被判为显著**，所以"**与零不可区分**"这一结论是**稳健**的
（保守方向）。⇒ 只能写"**点估计非劣**"，不得写"严格支配"。

**多重比较**：Block 9 比较 6 方法、Block 8 比较 2 层、Block 6 比较 3 情景 —— 全部
**未校正，属描述性枚举**。本工作**唯一**的预设推断性对照是 Block 9 的召回差值，它不是多重比较族的一部分。

**软件口径**：区间由 `compute_all.py` **手写实现**（Wilson 得分区间 `wilson`、Newcombe 混合得分差值区间 `rd_ci`），
**未使用 scipy**（本机不可得）。公式可逐行核对，无第三方黑箱。
