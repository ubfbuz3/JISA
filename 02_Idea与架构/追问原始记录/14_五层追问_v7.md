## L1 PROBLEM FRAMING（问题定义与动机）

### Q1 `[Q:CHALLENGE]` C2 的"假确证"基准在 catalog 级不可观测，却支撑了整条因果链
C2（13_r7 §3→§C2）把"假确证"归因从第六轮的"tester 账本 `share_log`"改写为"授权状态与 GUI 视图不一致"。但你已在第六轮撤回"`share_log` 是权威真值"（Idea判断 §2.3、§2.4）。现在新基准 = "app 的授权状态表"（S6/S7 中 `can_access` 读授权表、判定"仍完全正确"）。问题：**catalog 级证据里只有 MR 声明（`catalog_text.txt`），没有任何"GUI 爬取日志"或"授权状态表"的可观测量**。你用结构断言（门控谓词来自 GUI）去推断"运行时会假确证"，但"假确证"本身是一个运行级现象。这与硬条件④（跑原生引擎，EXPERIMENT_RESULTS.md §限制1、Idea判断 §5 条件4"不做必被拒"）**直接冲突**——你自己也承认 13_r7 §5"仍是目录级/源码级证据，不是运行级证据"。
> **如果答不上来，后果**：C2 从"我们证明 MST-wi 会误报"退化为"我们假设它会"，失效命题失去运行级支撑，与硬条件④的缺口同时暴露。

### Q2 `[Q:CHALLENGE]` C1 的"13–18%"把四个不可通约的口径当成同一量的置信区间
作者并列四口径：模式表 `different user`=8 / `changeCredentials`=9 / 名称 `AUTHZ`=10 / 并集=14，并称"保守陈述：授权相关 MR 占目录 13–18%"。**已独立核实这三处断裂**：
- 模式表 `different user`=8 的 8 行含 **CWE_289a（认证绕过）、CWE_488、CWE_200（信息暴露）**——这些不是对象级授权（BOLA/BFLA），是认证/会话/信息泄露类；
- 并集 14 中 **OTG_AUTHZ_001a、OTG_AUTHZ_001b、CWE_15_639_OTG_AUTHZ_004** 在模式表 `different user`=**0**（已独立核对 catalog↔patterns 命名映射：CWE_138/CWE_20/CWE_15 行）——即"不同执行主体"口径与"名称含 AUTHZ"口径对同一条 MR 给出相反判定；
- 作者的"13–18%"**排除了** 10.5%（`different user`=8）与 11.8%（`changeCredentials`=9）两个下界，真实跨口径散布是 **10.5%–18.4%**，作者取了偏窄的上半段。
这四个数测量的是四个不同构造（跨主体认证绕过 / 凭证变更 / 命名惯例 / 并集），不是同一真值的四个估计。"授权相关 MR"的定义本身未固定。
> **如果答不上来，后果**：C1 的分子分母同时失稳，"刻画边界"失去被刻画的对象，覆盖薄/厚之争无法成立。

### Q3 `[Q:CLARIFY]` "82–87% 不改执行主体"的 82–87% 来自减法口径，按 `different user`=8 实为 89%
作者由 76−14（并集）或 76−10（AUTHZ）得 62–66 ≈ 82–87%。但模式表可观测的"跨主体"MR 只有 8 条（已独立核实），即 **68/76 = 89%** 不改执行主体。作者选了最窄的可信带且偏向让"覆盖缺失"显得最强。属口径选择偏置，需在论文中显式报 68/76(89%) 与 62/76(82%) 并说明取哪一个、为何。

## L2 METHODOLOGY（方法选择与最大弱点）

### Q4 `[Q:CHALLENGE]` 杀招2·消融：v3 的核心（自省面读取）若被直接授权查询严格支配，机制即冗余
v3 = "MR 触发 + 自省面比对"。在自省面可读时，去掉 MR 触发、只保留"以拥有者身份 `GET /shares` 并比对 requester≠owner"的**直接授权查询**，是否在每个 v3 处理的 case 上得到相同乃至更多 TP、且不引入 v3 在 `unlisted` 下的 FN？EXPERIMENT_RESULTS.md 只报了 v1/v2/v3/`degrade_all`，**没有 "direct-authz-probe" 这一消融组**。若直接查询严格支配 v3，则 MR 只是冗余触发器，论文贡献塌缩为"用 SUT 授权 API 作 oracle"——这**不是变形测试贡献**。
> **如果答不上来，后果**：最得意组件被证非必要，机制标题与"MT 方法论"脱钩，N 无法抬升。

### Q5 `[Q:PROBE]` 冲突时谁有优先权：v3 内部 GUI 门控与自省面比对的裁决规则未声明
v3 同时应用 MST-wi 式 GUI 门控（`cannotReachThroughGUI`）与自省面比对。二者冲突（GUI 说不可达但自省面说 B 有权；或反之）时，Block 8 只报 on/off 聚合，未给逐 case 裁决规则。若自省面优先 → GUI 门控是死代码；若 GUI 优先 → 退回 C2 的假确证。机制内部存在未声明的优先级，两种优先级都削弱贡献。
> **如果答不上来，后果**：v3 在不同系统上行为不可预测，可复现性与可容许条件的操作性同时受损。

### Q6 `[Q:CLARIFY]` C4"刻画 + 带可容许条件的机制"——本轮新证据只动 E 维，未动 N 维，却用于回应 N 维 blocking
v3 机制在第六轮已提出；本轮 catalog 普查不新增机制。第六轮判决（Idea判断 §1）明确"N=2 是唯一下拉项，多跑实验抬不动 N"。你用 E 维证据（覆盖率从 2/76→全目录）回应一个 N 维 blocking（真实世界发生率→N），属维度错位。13_r7 §0 自己也写"外推凭据从 2/76→全目录普查"——外推凭据是 E，不是 N。

## L3 EVIDENCE（什么能说服 / 什么能推翻 / 担心找不到什么）

### Q7 `[Q:CHALLENGE]` 杀招1·循环论证：v3 用"被测系统自报的授权状态"判定"被测系统是否授权错误"
自省面（`GET /shares`）读的是 app 自己的授权表；S6/S7 的"真值"也是 `can_access` 读同一张表。当漏洞恰是"授权状态本身错误"（错误配置 / 越权委派 / 第三方共享未入表）时，自省面自证其"正确"，v3 给出假确证。你的"可容许条件"**只门控可读性，不门控自省面的正确性与完备性**。你把循环从 tester 账本移到了 app 授权表，循环未破。
> **如果答不上来，后果**：C2 的失效模式未被真正修复，只是从"tester 账本不一致"换到"自省面可读但错误"的新发生位置，假确证仍在。

### Q8 `[Q:CHALLENGE]` 什么证据能推翻你：`isUserIdParameter` 在论文 0 命中，却正是 OTG_AUTHZ_003 的门控谓词
你自陈"0/76 以授权制品状态作门控"是最弱但可穷尽验证的命题（13_r7 §3 末）。**已独立核实** `isUserIdParameter` 在 `mstwi_paper_text.txt` 全文 0 命中（grep→0），而它正是 OTG_AUTHZ_003 的门控谓词（`catalog_census.csv` 行 71，`authz=True`）。若 `isUserIdParameter` 属"授权制品状态"类（参数即用户标识 ⇒ 谁对哪个对象持何权限的结构化表达），则"0/76"变"≥1/76"，最强子声称直接破。你把它标"需核实"却**未核实就拿它当前提**。
> **如果答不上来，后果**：核心刻画"MST-wi 从不以授权状态门控"在破洞补前不可宣称，C1 最强命题作废。

### Q9 `[Q:CHALLENGE]` `crtg` 列含义未定义却覆盖 7 条授权 MR，使"0/76"与"12/14 同族"同时不可穷尽
`catalog_census.csv` 第 7 列 `crtg` 对 CWE_266/280/286/289a/302/306/601 共 7 条授权 MR 为 True，但 13_r7 §1.2 的白名单（7 谓词）未定义 `crtg`。`crtg` 若是 `cannotReachThroughGUI` 别名则无害；若是 `isUserIdParameter` 或某种归属检查，则"0/76 授权状态"与"12/14 同族"**同时失稳**。你提交了一份含未命名谓词的普查表却据此下结论。
> **如果答不上来，后果**：C1 的"门控同族"与"0/76"两条同时需要重做，普查的可穷尽性自称被自身数据推翻。

### Q10 `[Q:CLARIFY]` 你担心找不到什么：硬条件④（原生引擎）仍"未解除"
EXPERIMENT_RESULTS.md §限制1 与 Idea判断 §5 条件4 仍将"跑 MST-wi 原生引擎"列为"不做必被拒"。你本轮用 catalog 普查替代运行级证据，但 13_r7 §5 自己承认"不是运行级证据"。审稿人"你从未证明 MST-wi 在真实 BOLA 应用上实测失效"这一问，本轮仍无答。

## L4 CRITICAL SELF-EXAM（假设崩塌 / 反方驳 / 最脆弱处）

### Q11 `[Q:CHALLENGE]` 假设崩塌：若 Nextcloud/Gitea 实测预存授权发生率极低，或 GUI 与授权状态高度一致

> **如果答不上来，后果**：贡献的实际适用范围塌缩到受控实验，期刊级普遍意义丧失。

### Q12 `[Q:PROBE]` 反方驳：你已在材料里自我撤掉 C1 的覆盖论点，只剩三处破洞的"门控同族"
13_r7 §5.5 自承"若按上界口径 14/76，'授权覆盖薄'叙事被削弱（18.4% 不算薄）"，并主动把主张从"覆盖薄"改为"覆盖虽在、但门控同族"。即 C1 的覆盖论点已被你**自己撤回**。而"门控同族"又受 `isUserIdParameter`（Q8）/ `crtg`（Q9）/ `CWE_200`（13_r7 §3 末"需人工复核"）三处破洞。反方只需守住这三处即可让 C1 全废。你是否在用一份自承薄弱的材料做主打证据？

### Q13 `[Q:STRUCTURE]` 最脆弱处：攻击目标（MST-wi 漏检 BOLA）始终是结构推断，不是实证
全篇依赖"MST-wi 特异性 99.81% 建立在与真实授权状态一致的前提"这一推论，但该推论来自 catalog 结构分析。你既未跑原生引擎（条件④），又无真实 BOLA 应用（条件⑤）。两缺叠加，"MST-wi 漏检 BOLA"始终是**结构推断**，不是运行证据。整篇立足点悬空。
> **如果答不上来，后果**：攻击目标未被坐实，从"发现框架边界"降为"对公开 DSL 的重新解读"。

## L5 SIGNIFICANCE（"so what" / 是否够期刊级方法贡献）

### Q14 `[Q:CHALLENGE]` 杀招3·全做通了仍不构成贡献：核 = 重述公开 DSL + 一条 oracle 选择常识
即便 576 条全绿、自省面可读时恢复 1.00 / 假确证 0 / 检测力 1.00 全部成立：你的贡献核 = "MST-wi 的 MR 门控在 GUI 可达性；测 BOLA 应读 SUT 授权面，不可读则弃权"。这等价于安全测试常识"有权威 oracle 就用、没有就弃权"，且 MR 被直接授权查询严格支配（Q4）。对于 CCF-C 期刊，重述公开 DSL 定义 + 一条常识性 oracle 原则，是否够"method"而非"correspondence / lesson-learned"？第六轮已判"体裁下移"，本轮未新增机制或新颖性。

### Q15 `[Q:CHALLENGE]` "so what" for 实践者：你指出的"边界"在 MST-wi 里是可被用户自行填补的 feature
MST-wi 的 DSL 有 55 个专用函数、允许用户自定义 oracle（你自己在 EXPERIMENT_RESULTS.md 用 `isUserIdParameter` 类扩展即为例）。即你指出的"门控同族"在 MST-wi 框架内只是"用户没写授权 oracle"——是可被使用者自行填补的，而非框架性缺陷。实践者读完应改变什么行为？若答案是"使用者本就该写授权 oracle"，则你的发现是 documented-but-unused feature，不是 gap。
> **如果答不上来，后果**：贡献从"揭示框架缺陷"降为"提醒用户用已有功能"，实践意义近零，期刊录用动机消失。

### Q16 `[Q:CLARIFY]` 本轮是否改变第六轮判决：若你接受"N 未动"，则 FINER 仍 3.8、"不可以"维持
