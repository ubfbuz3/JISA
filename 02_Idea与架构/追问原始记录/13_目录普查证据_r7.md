# 第七轮新材料 · MST-wi 目录全量普查（可独立复算）

> 用途：为第七轮苏格拉底追问提供**不依赖新实验**、但**任何人都能从公开制品复算**的证据。
> 制品：`01_文献调研/mstwi_artifact/`（`PatternsOfMRs.xlsx`、`catalog_text.txt`、`mstwi_paper_text.txt`）
> 机器可读产出：`refine-logs/catalog_census.csv`（76 行逐条特征）、`refine-logs/catalog_patterns.csv`（论文模式表导出）
> 脚本可重跑；下列每个数字都注明其统计口径。

---

## 0. 为什么需要这份材料

第六轮把审判卡在 **Novel（N=2）**，并断言"多跑实验抬不动 N"。
第六轮同时暴露一个**证据结构缺陷**：我只移植了 **2 条** MR，
于是"MR 框架在对象级授权上丧失辨识力"这一主张的外推凭据是 **2/76** —— 极单薄，
而且我**从未给出授权 MR 在目录中的实际占比**。

本轮把这一项从"抽样印象"升级为"**全目录普查**"。它不需要新实验，只需要读完已下载的制品。
它能同时回应硬条件 ⑥ 与必答 Q3 的一部分。

---

## 1. 方法（可复算）

1. `catalog_text.txt` 用 `\bMR\s+([A-Za-z0-9_]+)\s*\{` 提取 MR 声明 → **76 条**
   （与论文自述"76 MRs"一致，互为交叉验证）。
2. 逐条用**括号配对**截取 body（非"到下一声明"，避免串块），剥除 `/* */` 注释，
   再检索谓词：`userCanRetrieveContent` / `cannotReachThroughGUI` / `isSupervisorOf` / `isAdmin` /
   `changeCredentials` / `parameterValuesUsedByOtherUsers` / `LoginAction(User())`。
3. `PatternsOfMRs.xlsx`（Sheet1，76 行 × 13 列）＝论文模式表，其 `User → different user` 列给出**独立的第二种口径**。
4. `mstwi_paper_text.txt` 的 DSL 函数表给出**谓词权威定义**，用于判定"该谓词取自何种信息源"。

## 3. 结果 B · 授权 MR 的门控谓词几乎全部来自 GUI 可达性或主体属性（本轮最强证据）

论文 DSL 表的**权威定义**（原文摘录）：

| 谓词 | 论文原文定义 | 信息源性质 |
|---|---|---|
| `userCanRetrieveContent(User u, Object out)` | "true if the output data has **ever been received in response to any of the input sequences executed by the given user during data collection**" | **爬虫采集日志** ⇒ GUI 派生 |
| `cannotReachThroughGUI(User u, String URL)` | "true if a URL **cannot be reached by the given user by exploring the user interface** of the system (e.g., by traversing anchors)" | **GUI 遍历** ⇒ GUI 派生 |
| `isSupervisorOf(User a, User b)` | "true if **'a' can access the URLs of 'b'**" | ⚠️ **亦为 URL 可达性** ⇒ GUI 派生 |
| `isAdmin(User u)` | （主体静态属性，非对象级） | 角色属性 |

**统计**：

| 量 | 值 |
|---|---|
| 并集 14 条中，门控谓词取自 {GUI 可达性, 采集日志, 主体属性, 参数身份} | **12 / 14**（86%） |
| 并集 14 条中，门控谓词取自 **GUI 派生**（不含 `isAdmin`） | 11 / 14 |
| 全目录依赖 GUI 派生谓词的 MR | **38 / 76（50%）** |
| 其中 `userCanRetrieveContent` | 32 条（出现 54 次） |
| 其中 `cannotReachThroughGUI` | 8 条 |
| 其中 `isSupervisorOf` | 7 条 |
| 其中 `isAdmin` | 2 条 |
| **以"授权制品状态"（谁对哪个对象持何种权限）作门控的 MR** | **0 / 76** |

**★ 与第五、六轮相比的一处实质修正**：
我此前把 `isSupervisorOf` 归为"主体-主体关系谓词"（E2，与 `userCanRetrieveContent` 属**不同类**）。
**这不准确**——按 MST-wi 自己的 DSL 表，`isSupervisorOf` 被**定义为 URL 可达性**，
因此它**同样是 GUI 提供性代理**，只是套了一层角色语义的外衣。
⇒ 这使得"授权门控谓词同族"的证据比第五轮**更强且更可穷尽验证**。

**两条例外**（必须如实列出，不得隐去）：
- `OTG_AUTHZ_003`：门控是 `isUserIdParameter(...)`；该函数在论文全文 **0 次出现**（不在 DSL 表中）⇒ **需核实**。
- `CWE_200`：只命中 `changeCredentials`，未命中任何 GUI 谓词 ⇒ **需人工复核**（我读到的 Idea 段是
  "a file path passed in a parameter should never enable a user to access data **that is not provided by the user interface**"，
  即仍是 GUI 提供性口径，但其 body 的 `changeCredentials` 用法未逐行确认）。

⇒ 可给出的**最弱但可穷尽验证**的命题：

> **在 76 条 MR 中，没有任何一条以"授权制品状态"作门控谓词；
> 授权相关 MR 的门控谓词主要取自 GUI 可达性/采集日志，其余取自静态主体属性或参数身份。**

（**注意**：这**不是**"对象级谓词零命中"——那个断言已在第五轮撤回，**不得**再用。）

## 4. 结果 C · 佐证：目录与论文的词汇里没有"授权状态"这一维度

对 `mstwi_paper_text.txt` 全文（小写化）词频 + **逐条抽样看上下文**（第六轮教训：词频不可信）：

| 词 | 次数 | **抽样后的结论** |
|---|---|---|
| `owner` / `ownership` | **0 / 0** | 全文无"所有者"概念 |
| `delegat` | **0** | 全文无"委派"概念 |
| `share` / `shared` | 2 / 2 | ⚠️ **两处语境均与授权无关**：`shared remote server`、`shared appointments` |
| `permission` | 13 | 抽样：CWE 名称（Incorrect Default Permissions）、管理员权限、文件系统权限——**均非对象级授权状态** |
| `privilege` | 10 | 抽样：含**关键锚点句** "we need a mapping between roles and resources, **which is not always available**"（已核实，line 74） |
| `acl` | 103 | ⚠️ **全部是 `oracle` 的子串**（第六轮已确认，本轮复现） |

⇒ 与结果 B 互证：MST-wi 的授权概念 = **角色/特权 + URL 可达性**，
**不含**"对象归属 / 共享 / 委派"这一维度。

## 5. 这批材料能带来什么 / **不能**带来什么

### 能带来

1. **外推凭据从 2/76 → 全目录普查**：授权相关 MR 占 13–18%，且门控谓词 12/14 属同族。
   ⇒ 硬条件 ⑥（授权 MR 覆盖面）**在目录层面已可回答**；必答 Q3（泛化凭据）**部分可回答**。
2. **主证据从"我移植了 2 条"升级为"目录结构本身"**：不再依赖我的移植保真度。
3. 提供一个**任何人可复算**的表（`catalog_census.csv`），E（证据）维度显著抬升。

### **不能**带来（必须自行声明）

1. **仍是"目录级/源码级"证据，不是"运行级"证据**。它证明的是**目录的表达力边界**，
   不是 **MST-wi 在真实系统上的实测失效**。⇒ 硬条件 ④（跑原生引擎）**未被解除**。
2. **没有任何真实系统的发生率数据**（必答 Q1 仍空）。⇒ **N 未被抬升**，判决可能不变。
3. `parameterValuesUsedByOtherUsers` 与 `isUserIdParameter` 在论文 DSL 表中**查不到定义**
   ⇒ 涉及二者的推断必须标**"需核实"**。
4. **口径分歧（8/9/10/14）本身就是弱点**：审稿人可质疑"你连分母都定不下来"。
   ⇒ 必须在论文中**并列四种口径**并说明各自的判定标准。
5. 若按上界口径 14/76，则"授权覆盖薄"这一叙事被削弱（18.4% 不算薄）。
   ⇒ **主张必须从"覆盖薄"转向"覆盖虽在、但门控同族"**，否则会被 14/76 直接打掉。
