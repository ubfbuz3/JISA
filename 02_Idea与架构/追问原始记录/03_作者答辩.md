## 0. 答辩立场声明（先行坦白）

对手方两条独立路径（A 路五层追问、B 路拒稿备忘录）收敛到同一个 Critical，我必须先正面回应而不是绕开：

> **方案证明的是「攻击者访问到了受害者对象 / 改变了它的状态」，不是「攻击者本不该有权这么做」。定义 BOLA 所必需的谓词 `forbidden(i, o_A, e)`，方案并没有独立获得——它是从实现制品（ORM 归属字段、SQL owner 谓词）近似来的。**

**我接受这个技术判断的核心。** 在方案当前形态下，`confirmed-read` / `confirmed-write` 的准确语义是「跨账户对象访问被证实发生」，把它直接称为 BOLA 确证，是**表述越界**。

但我不接受「因此这套东西全盘不成立」。下面分三层说清：哪些我承认、哪些我认为对手方的标准过严、以及我认为唯一能站住的重构是什么。

## A. 对 Critical 核心攻击的答辩

### A1. 「缺 forbidden 谓词 ⇒ 循环验证」——接受技术判断，不接受全盘否定

**我承认的**：`OwnerFields` 是数据关联（谁创建了它），不是授权规则（谁被允许访问它）。「有 owner 字段」既不蕴含「只有 owner 可访问」，「缺 owner 谓词」也不蕴含「缺检查」——因为检查可能在中间件、可能在 service 层、可能在数据库行级策略里。方案的证据图覆盖不到所有位置，这一点我没有反驳。

**我不接受的**：把「拥有独立形式化政策真值」当作及格线。理由三条：

**(1) 这是领域共同前提，不是本文独有缺陷。** BolaRay[Hua24] 从 SQL + 静态分析推断「应当存在的 owner check」，同样不携带独立政策真值；MOCGuard[Liu25c] 从 DB 结构推断「用户拥有哪些数据」，也是从实现反推规范；BACFuzz[Dha25] 的 SQL oracle 检测越权读，同样没有策略规格输入。若「必须有独立于实现的形式化政策真值」是及格线，这三篇一起不过——包括 CCS'24 和 IEEE S&P'25 的工作。**这条标准可以使用，但必须对本文与同期工作用同一把尺子。** 若审稿人接受 BolaRay 的 193 个确认漏洞，就不能仅因本文缺政策真值而拒稿。

**(2) fault 306 原文反对的不是「推测」，而是「把推测说成判定」。** 原文："it is hard to say automatically if we are in the case of a BOLA/BFLA vulnerability. **Still, some heuristics could be used to flag highly suspicious cases.**" 它承认推测是当前唯一可行路径，只是要求别声称为判定。本文的方法不是取消推测，而是**给推测加上归属证据维度、缩小其适用范围、并公开划清边界**。

**(3) 缺口的修法存在，成本可控，且方案里现在没有。** 补第四组对照——**已知合法跨账户访问**（显式实现共享 / 管理员访问的配对端点）：

- 若方法在合法共享端点上给 `confirmed` → **C2 被自己的实验证伪**，方法不成立；
- 若方法在合法共享上给 `likely` / `inconclusive`，而在真正缺检查的配对上给 `confirmed` → **「可判定边界」的主张获得直接实验证据**。

**这是本轮追问最实质的收获，我承认这是方案必须补的，且现在没有。**

### A2. 「fault 306 是偷换：工具局限 ≠ 问题现实」——接受一半，并同意修改措辞

**接受**：fault 306 只能证明「EvoMaster 这个 oracle 选择了启发式」，**不能**直接推出「现实 API 的授权规格普遍无法表达」。方案 v3 §2 的标题「把规格缺失钉成可引用的硬事实」**措辞过强，同意改**：fault 306 提供的是**问题被 SOTA 工具承认存在**的动机证据，**不是缺口大小的量化证据**。量化只能来自 L0 实验。

**接受但需澄清**：C1 在 v3 §2.1 里已经被写成可证伪（「动机实验给出硬数字」）。所以「工具局限 vs 问题现实」的跳跃在**方法上是待验证假设**，在**措辞上是既成结论**——问题出在措辞。

**我承认 U1**：L0 的 clause 切分单位、双标注协议、分歧仲裁规则**完全未定义**，标注者可见信息范围也没界定。若不定义，C1 无法证伪。

**修法（新的，方案里没有）**：
- 切分单位冻结为「(主体角色, 动作, 对象类型) 三元组上的允许/禁止条件」一条 = 一个 clause；
- **双标注 + 第三方仲裁**，分歧率单独报告；
- **关键隔离**：标注者**只能看到方法的输入制品**（OpenAPI + 路由 + 中间件 + ORM + SQL），**看不到运行时结果**——否则标注者会被方法输出污染，循环成立。这一点如果做不到，C1 必须降格为描述性统计。

### A3. 「VAmPI 孪生不是干净阴性对照」——接受降格，但指出范畴错误

**接受的两点**：
1. `:5001 静默` 不能直呼 FPR——因为排除表由作者定义，边界不可外部验证。**同意降格措辞**为「对该版本、该冻结端点集的配对行为一致性」，并**逐项报告 5001/5002 的原始响应与人工类别**。
2. 方案没有要求做 **5001 vs 5002 的代码 diff 审计**来证明「只有授权检查不同」。**同意补**：若无 diff 可审计，配对前提不成立。

**不接受的一点（范畴错误）**：对手方称「孪生只验证一个开关的差异敏感性，没有验证方法对真实政策的正确性」——**这正是阴性对照的定义**。阴性对照的功能从来是「证明方法不会对已知安全实现乱报」，不是「证明方法对任意政策正确」。要求阴性对照承担正确性证明，等于要求对照组回答它不负责的问题。

**但接受加重条件**：既然 L2 只能担「回归/误报抑制」角色，C2 的效度就不能挂在 L2 上，**必须挂在 L3（含合法共享负例的构造式配对）上**。这意味着 **L3 从「补充层」升级为「C2 的主证据层」**，方案的地位安排要改。

### A4. 「C3 是循环验证：真值、排除表、mutation 都由作者控制」——接受，并给出唯一出路

**接受**：在作者同时控制真值生成、排除表与 mutation 形态的前提下，全部实验跑通也只能证明「作者选定的实现模式与作者所定标签之间的一致性」。

**三条缓解路径**（前两条我承认方案没有，必须补；第三条是重构）：
1. **独立复现者**：第二组审计者在不知道系统 verdict 的前提下，用**隐藏的政策标签**核验每一个 `confirmed` 是否真的违反授权；
2. **独立政策标签的来源**：至少一部分真值不能由作者写——例如采用应用**自带的、作者未参与设计的**官方缺陷清单（L1）作为外部锚点；
3. **重构承诺边界**：不再声称「证明方法正确」，改为**「量化方法的可判定边界与弃权行为」**。循环性从「致命伤」降为「贡献边界的显式声明」。

## B. 对 B 路三处攻防的逐条答辩

### B1. 立论基石（对手方评分 2/5 → 我答辩后请重评）

对手方加压方向是：「要求作者在不接触运行时结果的前提下，给出独立、预先冻结、逐 clause 可审计的政策真值来源；若做不到，C1 只能写成描述性统计。」

**我的答辩**：这条要求对 C1 成立，但 C1 **本来就不是**「我们有政策真值」这个主张。C1 的主张是**否定式的**：现存表示（OpenAPI + 启发式）**不足以覆盖**决定端点访问权所需的 clause。这是一个**覆盖率的测量问题**，不是政策真值问题。

打比方：要证明「CT 扫描漏掉了骨折」，不需要知道骨折的最终诊断标准是什么，只需要请放射科医生独立标注「这张片子有没有骨折」，再看 CT 报告有没有写。医生的标注当然带主观性——所以要有双标注、分歧率和仲裁规则。**但这不构成循环**，因为医生的标注是独立于 CT 输出做出的。

对手方会反驳：医生的标注也是一种"政策模型"。**接受**——所以 C1 只能声称「相对于独立人工标注，现有表示存在 X% 的覆盖缺口」，**不能**声称「现有表示与真实政策差 X%」。这个限定我接受，且它不影响 C1 作为动机的成立。

### B2. 核心仪器（对手方评分 3/5）

对手方要求把 L2 降格为「配对行为一致性」，不得称 FPR。**接受**（见 A3）。

但对手方最后一句「VAmPI 可保留为工程回归测试，**不能作为 C2 的核心效度仪器**」——**接受**。这正是 A3 的结论：C2 的主证据层要从 L2 移到 L3。

### B3. 核心方法（对手方评分 2/5）

对手方结论：「当前 verdict 是『跨账户对象效果确认器』，不是 BOLA 判定 oracle。」**接受这个措辞判断**。

对手方给出的加压方向很具体，也是我认同的修法：**必须设计含合法跨账户共享/管理员访问、且在响应、对象存在性、自有对象成功上与 BOLA 完全相同的正交对照**。若系统仍判 confirmed → C2 被证伪；若需人工添加政策 → 论文必须承认 oracle 依赖人工规格。

**我接受这个设计，并承认它在方案里没有。** 这是本轮的第二项实质收获（第一项是 A1 的第四组对照，两者是同一件事）。

## D. 我认为对手方标准过严 / 范畴错置之处（附理由）

### D1. 「必须有独立于实现的形式化政策真值」——领域级标准，非本文级

如 A1(1) 所述，BolaRay、MOCGuard、BACFuzz 都不满足这条。**若这条成为拒稿理由，它拒掉的是整个 BOLA 检测方向。** 本文接受「不能声称 policy ground truth」，但不接受「因此本文不如同类工作」。

### D2. 「与 EvoMaster 比较不公平」——接受不可比，但给出可比化方案

对手方说 EvoMaster 输出「likely should have been protected」告警、本文主指标只计 `confirmed-*`，两者是**不同语义的告警集合**，paired 比较无统计解释。**接受这个批评**。

但可比化路径存在：
- **共享真值集**：由**独立审计**（不是任一方方法的输出）在固定端点集上给出「是否为真 BOLA」的标签；
- **两个方法在同一真值集上算 precision**：EvoMaster 的 306 告警中经审计确认的比例 vs 本文 `confirmed` 中经审计确认的比例；
- **相同请求预算**，配对单位 = **应用**（不是请求）。

这样比较的对象是「同一真值、同一预算下的精度」，而不是「两个不同语义的告警数量」。**我承认方案 §4.3 第 1 条没写这些，必须补。**

### D3. 「退守线」——接受但不接受退到「测试框架」

对手方给的最低可接受 claim 是：「一个面向已知或外部给定授权策略的、可复现的多账户 API 行为测试与证据记录框架。」

**我接受它的诚实性，但认为它退过了头**——退到这一步，贡献就变成纯工程 artifact，三区期刊的方法创新要求难以满足。

**我认为可守的更强版本**：
> **一个刻画 BOLA 运行时可判定性边界的状态校准裁决协议**：它显式给出「在什么条件下，跨账户对象访问可以被确证为 BOLA；在什么条件下必须弃权」，并在官方安全孪生（误报抑制）与含合法共享负例的构造式配对（确证正确性）上分别量化。

这条更强版本的合法性来自 fault 306 的**反面**：fault 306 之所以要「退守启发式」，正是因为它**没有刻画这条边界**。刻画这条边界本身是有价值的机制性贡献，而不是「把已有部件拼起来」。

**它可被攻击的点我也先说了**：边界是否有实际区分力，取决于边界内确实能确证一批真实 BOLA、边界外确实无法判定。这需要 L3 的数据支撑，**现在还没有**。
