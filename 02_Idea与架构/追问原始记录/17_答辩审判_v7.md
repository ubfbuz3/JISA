### 0.2 但这是一场稻草人消融（核心攻击）

**致命点：direct-only 在 (config, scenario) 组级别缓存 `probe_state` 并**统一**套用到组内每条记录，且它完全不消费"本次访问是否真的成功"这一观测。**

`ground_truth` 的真值公式是（`mrs/engine.py:272-289`）：

```
BOLA ⟺ (app_allowed = status==200)  AND  (¬ should_allow = ¬can_access)
```

其中 `app_allowed`（请求是否返回 200）是**直接可观测**的——发一次请求看响应码即可，**不需要任何变形关系**。而 `should_allow` 才是授权判定（即 introspection probe）。

再看 MR 的触发到底观测了什么（`mstwi_mrs.py`）：
- **MR-004** `triggered = ¬out2.is_error AND ¬can_retrieve`（`mstwi_mrs.py:156-158`）=「访问返回非 4xx（即 `app_allowed`）**且** GUI 不可见」。
- **MR-002** `triggered = precondition AND (¬out1.is_error AND out1.equals(out2))`（`mstwi_mrs.py:262-263`）=「A 的访问成功（`¬isError`）**且** B 拿到相同输出」。

**也就是说，MR 触发本身所依赖的"访问证据"= HTTP 200，这恰恰是非变形的、单请求可直接观测的量。** 作者所谓"MR 提供必要的访问证据"，拆开看是"MR 提供了 HTTP 响应码"——这不是变形测试贡献。

而作者的 direct-only 基线**既不消费 MR 观测，也不消费访问成功观测**（它只看组级 `probe_state`）。于是在"none"组里，它对**所有**记录（包括本就被正确拒绝、status==403 的正常记录）一律报警 → 108 次 FP 全部落在 `probe_state=="none"` 的组（`ablation_direct.json` per_scenario：S1/S2/S4/S7 各 +24 FP，S5 +12 FP）。

**一个公平的"无 MR"基线应当是：alarm ⟺ (observed 200) AND (introspection none)**——即直接观测访问结果 + 查授权面。该基线的正常记录（正确拒绝，status==403）会判为 TN，**108 个 FP 全部消失**，精度回到 ~1.0，且仍不依赖任何 MR。作者**没有跑这个基线**。

⇒ 因此：消融证明的是"你必须同时检查'访问是否成功'和'是否授权'"，而"访问是否成功"是非变形的。它**没有**证明"变形测试（MR）是必要的"。Q4/U9 作为方法论攻击**未被驳倒**，且作者连真正相关的对照（含访问结果观测的直接探测器）都没做。

### 0.3 附带发现：v3 的 recall 只有 48.6%，作者刻意回避

`ablation_direct.json`：v3 recall = 105/216 = **0.4861**，且 v3 的 FN=111 **远大于** v2 的 FN=3、v1 的 FN=18。即 v3 把 v2 的 60 个 FP 换成了 **108 个 FN**——对安全检测器而言，用"静默漏报"替换"误报"通常**更糟**。作者只庆祝"precision 1.0000、误报 0"，却不报 recall 塌到 48.6%（F1≈0.654）且主导错误是漏报。这是新的 Critical 点（见 C-12）。

## 2. 对作者反问 R1 / R2 / R3 的回答

### R1（二选一：对 99.81% 适用域的更正，还是已被 line 74 覆盖？）

**选 A——这是对 MST-wi 特异性适用域的一项真实、未充分声明的更正；但 A 与 B 并非互斥，且 A 成立不抬升 Novel。**

理由：MST-wi 原文 line 74 承认的是"角色—资源映射并非总可得"（一句弱前提）；而你指出的是更强的未声明前提"**GUI 可达性模型 ≡ 真实对象级授权状态**"——`0/76` 与 `12/14 同族` 共同证明 MST-wi 的判定锚定在 GUI 可达性/采集日志上，而非在授权态本身。所以 A 在技术上更精确。但 A 的产出仍是"把 line 74 的半句话展开成一张表"，属于**已知限制的实例化**（见 `15_备忘录 §3`）。⇒ 因此：**就算按 A 理解，Novel 仍为 2**，且这条只能作为 correspondence 级"度量分辨率注记"的头条（备忘录 L3/L4），不能支撑方法论文。

### R2（direct 0.5 vs v3 1.0 是否足以主张"MR 不可省"？若仍认为"MR 作访问证据发生器"属标准做法，请给出判据）

**不足以，且我给出判据。**

- 不足以的原因见 §0.2：该对照是稻草人，缺"访问结果观测"这一直接可观测量；公平的"无 MR"基线（observed-200 AND introspection-none）会消去全部 108 FP。故 0.5 vs 1.0 只证明"必须同时看访问结果与授权"，而访问结果=HTTP 200 是非变形的。
- **MT 贡献判据（可证伪）**：一条 MR 构成变形测试贡献，当且仅当它提供的判定信息满足 (a) 不能从单条请求的响应直接观测得到；(b) 不能由平凡的状态码/相等比较得到；(c) 其"关系保持"本身承载了关于被测系统不变量的推断。本方案中 MR-002/004 的"访问证据"= `¬isError(Out)`（状态码），属 (b) 平凡量；其真正"变形"的部分（`userCanRetrieveContent`/`cannotReachThroughGUI`）是 GUI 可达性代理，不是授权判定。故**本方案未满足 (a)(b)**，MR 必要性无法主张。作者若反驳，请先补跑 §0.2 的公平基线并报告其精度/召回。

### R3（可容许条件是否可推广概念？若可推广，什么条件才够 method 级？）

**它是披着原则外衣的局部补丁，当前未达 method 级。**

- 你提出的"仅当可读且非同类缺陷时方可升级"是针对"**SUT 自报 oracle 依赖**"这一特定失效模式的对策。作为通用原则"不要信任自报 oracle、需独立佐证"，它是软件测试关于 oracle 有效性的**常识**（非新）。所以它不具备跨框架的方法新颖性。
- 要达到 method 级，至少须：① 形式化一套通用 schema（对任意带可编程 oracle 的 MT 框架，给出 oracle-可容许性的判定规则与**可判定性/中止性**说明）；② 在 **≥2 个独立框架 / ≥2 类漏洞**上实证其 soundness 提升；③ 把"非同类缺陷"的人工判据**自动化或半自动化**。作者当前三条皆无。故 R3 的"可推广概念"目前不成立，只能作为 lesson 级注记。
