## 1. 三处自认最硬设计的攻防

### 设计①：全目录普查作为证据（C1）

- **steel-man（最强形态）**：作者声称把"2/76 外推"升级为"76/76 穷尽普查"，任何人可从公开制品复算；给出四种口径（8/9/10/14）并列，并得出"授权相关 MR 占 13–18%""门控谓词 12/14 同族""0/76 以授权制品状态作门控"三个可穷尽验证的命题。证据维度（E）从此前的"我移植了 2 条"升为"目录结构本身"，不依赖移植保真度。
- **攻击**：
  1. **分母定不下来，比例叙事自我崩塌**。四种口径 8/9/10/14 横跨 1.75 倍（10→14）。作者自己承认"若按上界 14/76，则'授权覆盖薄'叙事被削弱（18.4% 不算薄）"，于是把头条从"覆盖薄"**挪**到"门控同族"。这是典型的**移动球门**：你先卖"覆盖薄导致对象级盲区"，数据一查 18.4% 不薄，立刻改卖"门控同族导致判定失灵"。两个命题证伪方向不同，评审看到的是目标漂移。
  2. **0/76 是重言式，不是发现**。本人在 §0 已核实：全目录 `isOwner/canAccess/ownerOf/hasPermission/isAuthorized` **全部 0 次**，DSL Table 2 的 55 个函数**无一**是授权态谓词。因此"0/76 以授权制品状态作门控"等价于"一个没有罗盘的导航仪不指向北方"——**当然为真，且作者自己无法举出反例**（因为 DSL 里根本不存在那种谓词）。结论：C1 的"边界"是 MST-wi 设计选择的必然结果，不是被测出来的失效。

### 设计②：v3 + 可容许条件作为机制（C3）

- **steel-man（最强形态）**：作者把例外谓词数据源从"测试者账本 `share_log`"改为"被测系统自报授权面 `GET /doc/{id}/shares`"，面不可读时**强制弃权**。自省面 on 时 v3 恢复率 1.00 / 假确证 0.00 / 检测力保持 1.00，且把 v2 的 4 次假确证清零；自省面 off 时诚实弃权 13 次。可容许条件明确可测："仅当 SUT 暴露可读授权自省面，才允许升级为 `violation-proven`"。
- **攻击**：
  1. **机制在现实态下退化为弃权器**。自省面 off 时检测力保持率 = **0.00**（`EXPERIMENT_RESULTS.md` Block 8）。而"暴露可读授权自省面"恰恰是**多数真实 API 不具备**的属性（作者在限制 7 自承"自省面可读性是被构造出来的开关"，真实系统是否暴露"需在 Nextcloud/Gitea/Joomla 实测"——未测）。⇒ 在你最关心的"带外授权"场景里，v3 的现实收益 = **不报任何东西**。一个"仅在极少数系统上工作、在其余系统上沉默"的机制，作为方法论文贡献是**空操作**。
  2. **信任源的循环性（最隐蔽的硬伤）**。v3 用 SUT 自报的授权面当真理源。但 BOLA 的定义就是"授权系统本身把越权响应给了不该给的人"——你要检测的恰恰是这个端点的授权正确性。若 SUT 的 `GET /doc/{id}/shares` 自身有 BOLA（越权泄漏/隐藏 shares），则 v3 的"真理"被污染。作者 `app.py` 的该端点有 `doc["owner"]!=user→403`（line 251）是因为**作者写对了**；一个真实有 BOLA 的系统不会这么写。⇒ v3 只能抓"主资源端点的 BOLA"，抓不了"自省端点自身的 BOLA"，而后者正是同一类缺陷。作者把"构造式真值"换成"自报式真值"，但自报式真值在授权缺陷语境下依然可能自欺。
  3. **聚合口径继续掩盖制度性差异**。你自己在 Block 4 承认 v3 全局"检测力保持 0.4857"是 on/off 混算的产物；若作者不按 `introspection` 分层报（条件 4 之一），读者会误以为 v3 整体检测力近半。这是 M4 教训的**同款复发**。
  4. **相对 `degrade_all` 的优势仅在 on 态**。off 态 v3 检测力 0.00 = `degrade_all`（也是 0.00，但后者诚实）。即你的机制**只在它自己的前提成立时才优于弃权**——这等于"若条件满足则机制有用"，不构成独立贡献。
- **预判辩护**：作者会答——"可容许条件就是为 off 态准备的，诚实弃权优于 v2 的假确证（第六轮 A1）；循环性已被 `owner` 凭证约束缓解（需拥有者令牌，非任意用户）；off 态沉默是代价不是缺陷；Nextcloud/Gitea 实测会给出 on 态真实比例。"
- **辩护评分：2/5 → 继续加压**。辩护"诚实弃权优于假确证"成立，但救不了**贡献**：off 态=弃权器，on 态优势已被第六轮_B1 判为"不可比而非占优"。循环性仅靠"拥有者令牌"缓解，未论证"若拥有者令牌本身越权可读他人 shares"（即自省端点 BOLA）时如何。加压方向：① 逼作者在真实漏洞系统上演示"自省端点自身 BOLA"时 v3 是否失效；② 逼作者给出 on/off 在候选真实系统上的实测比例（否则"机制"的现实覆盖率未知）；③ 逼作者承认 v3 的净新增 = "把账本信任换成自报信任"，且后者在授权缺陷下非平凡更可靠。

### 设计③："带外预存授权"威胁模型的现实性

- **steel-man（最强形态）**：作者主张现实中存在"授权带外产生"——管理员配置、历史委派、第三方共享——使应用授权状态与 GUI 视图不一致，此时 MST-wi 式 MR 把合法访问误判为越权并贴 `violation-proven`。这是比"E3 不可表达"更强的经验补充（MST-wi 把误报归因于异步/时序，你指出另一类确定性的成因）。
- **攻击**：
  1. **威胁模型是你自己硬编码进玩具的**。`app.py` 中 `visible_in_listing()`（line 122–134）的 `unlisted` 分支**由作者写死**"共享仅对对象级端点生效、GUI 列举不体现"。也就是说，"GUI 视图 ≠ 授权状态"这一前提，是你**为实验特意构造**的不变量，不是你从任何真实系统观测到的。真实系统的 GUI 爬取与授权状态是否不一致、**以什么频率不一致**，你没有任何数据（Q1 空，限制 6）。⇒ 威胁模型的"现实性"是作者自证式造景，与第六轮_B2/B3 被部分驳回的"seed_share 自证式造景"同源。
  2. **"不一致→假确证"只在 unlisted 子情形成立**。你自己的 2×2 网格（附录 A Block 7）显示：`listed`（共享对 GUI 可见）时 MR 因 `cannotReachThroughGUI` 前置条件**不触发**，即**不误报**。所以 C2 的全称"带外授权⇒假确证"应收窄为"带外授权 **且** GUI 不可见⇒假确证"。而"带外授权且 GUI 不可见"在真实系统中的比例，你一无所知。全称表述在论文里若保留，即过度概括。
  3. **机制的前提吞噬了威胁模型**。"带外授权"之所以能被 v3 解决，前提是 SUT **暴露可读自省面**——但"暴露自省面"的系统，其授权状态通常**也**对 GUI/API 可观测（否则自省面本身也无意义）。即：v3 能解的"带外授权"子集，恰好是"授权态其实可被观测"的子集；真正"带外且不可观测"的子集，v3 只能弃权。⇒ 你用机制的前提**消解**了你要解的威胁，剩下的是你本来就能处理的情形。
- **预判辩护**：作者会答——"unlisted 是为可控性自建的最小反例，定位是受控实验而非发生率估计；S6 证明失效方向存在且边界单侧（不损检测力）；Nextcloud 的分享链接正是一例真实 unlisted 带外授权。"
- **辩护评分：2/5 → 继续加压**。辩护"受控实验非发生率"作者已在限制中声明，但声明不能替代**期刊要求的外部效度**；"Nextcloud 分享链接"是单例，不构成发生率。加压方向：① 逼作者把 C2 全称改为"仅 unlisted 不一致情形"，并在引言/摘要删除"带外授权必然假确证"类表述；② 逼作者给出≥3 个真实系统中"带外授权且 GUI 不可见"的发生率，否则威胁模型停留在"可能存在"；③ 逼作者说明 v3 的可解子集与"本就可观测"子集的重合度。

## 3. 「全做通也不算贡献」论证 → **Critical**

即便作者把上述所有实验、所有真实系统、所有原生引擎都跑通且结果如其所愿，本备忘录仍判定：**本稿不构成 JISA 方法论文贡献**。理由链：

1. **C1 是重言式 + 已知限制的复述**（§0/§1.①）。一个 DSL 不含所有权谓词 ⇒ 0/76 门控于所有权，是词汇表空缺的必然；MST-wi 原文 line 74 已自承"角色—资源映射并非总可得"。作者把半句话展开成表，未产生新事实。
2. **机制 v3 的净新增 = 信任源迁移**（账本→自报），且其收益**严格依赖**"SUT 暴露可读自省面"这一作者自承"被构造出来的"前提（限制 7）；在更现实的 off 态，v3 = 弃权器（检测力 0.00）。即机制只在它自己前提成立时优于弃权——不构成独立方法贡献。
3. **唯一被作者自己承认的"概念新意"**（第六轮 §3 "构造式真值可以不是关于被测系统的真值"）是一条**概念注记**，不是一套方法；且它恰由作者自己的 S6 反例引出，体量不足以撑方法论文。
4. **外部效度全缺**：N=2（2 条移植 MR / 1 个端点族）、自建玩具、无原生引擎、无真实发生率（Q1 空）、无跨厂商复核。第六轮已判 Novel=2 且"多跑实验抬不动 N"——因为 N 只由**真实世界发生率数据**抬升，而该数据在此稿中为零。
