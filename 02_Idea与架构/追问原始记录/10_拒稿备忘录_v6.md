## 设计 2：「可观测性边界」+ Boundary-aware 修正（含假确证）

**作者主张（附录 A / Block 6）**：E3 探测只在"共享操作对测试框架可观测"时有效；不可观测时失效方向是**把正确应用升级为 `violation-proven`（假确证）**，比原始误报更危险（带"已确证"标签）；S7 说明边界单侧（不损检测力）；并诚实修正 v2 恢复率 1.00→0.50。

- **steel-man**：这是附录 A 里唯一称得上"诚实"的部分——你没有把 S6 的失败藏起来，而是把它标成方法自身的边界（可观测性边界），并量化了失效方向（假确证率 1.00）。最强形态是：修正机制的有效范围被你精确刻画成一个可判定的条件（共享操作是否对框架可观测），且你坦承它 fail-open 而非 fail-safe，这是负责任的边界刻画。

- **攻击（打到骨头上）**：
  1. **S6 的"不可观测边界"是你自己账本的人为产物，不是被测系统的性质。** `seed_share`（`app.py:350-368`）直写服务端授权表，**不调用 `POST /doc/{id}/share`**，于是框架侧 `client.share_log` 为空（`engine.py:117-119` 的 `shares_of` 只读 `share_log`）。"可观测/不可观测"的定义 = "作者自己的 `share_log` 里有没有这条记录"。换句话说，**边界的两边（S3 可观测 / S6 不可观测）由作者是否把这次授权写进自己的账本决定**。任何真实 API 测试场景，测试框架要么有授权库读取权限（admin token / 测试账号）→ 可观测；要么完全没有 → 整个方法前提不成立。你制造了一个"我的仪器瞎了"的场景，然后把仪器的失明报告成"方法的边界"。这就是第五轮已被判为循环验证的**三人合一**（MR、被测系统、真值数据源同出一手）在附录 A 的借尸还魂——只是把循环点从 `share_log` 挪到了"是否调 API 写 `share_log`"。
  2. **"假确证"是修 bug 引入了更严重的 bug，且危害未量化。** 原始 MR 在 S6 上只产生一个 trigger（"疑似 BOLA，请人工核查"）；你的 v2 把它升级为 `violation-proven`（"已确证 BOLA"）。底层正确性同样是错的（正确应用被报缺陷），但**标签从"不确定"变成了"已确证"**。在安全 triage 工作流里，"已确证"会直接消耗分析师信任、触发误处置，而"疑似"至少保留怀疑。你量化了假确证**率**（1.00），却**没有量化其操作危害**（假确证数 vs 真阳性数的比值、或由此浪费的核查量）。谁来为这个新错误负责？你的修正机制。你把它当作"比误报更危险的发现"呈现，却没把它作为**代价行**与 v2 的"代价 0"并列报告——这是选择性诚实。
  3. **附录 A 自己拆掉了作者此前最强的消融论证。** 第五轮前（正文 Block 4、C3 证据表）作者的王牌是：「v2 恢复 1.00 **且** 保持检测力 1.00，*严格占优* degrade_all（后者恢复 1.00 但检测力 0）」→ 因此"对象级探测优于一律弃权"。附录 A（行 251–253）被迫承认：加入带外授权后 **v2 恢复 0.50 / 保持 1.00；degrade_all 恢复 1.00 / 保持 0.00**——二者不再是占优关系，而是**权衡**。更糟的是在 S6（不可观测）这一个 case 上，v2 的检测力仍 1.00 但恢复 0.00 且假确证 1.00，而 `degrade_all` 至少 fail-safe 到 `indeterminate`（诚实的不确定性）。即：**在不可观测情形，v2 严格劣于 degrade_all**（后者不制造假确证）。所以"对象级探测优于一律弃权"这个全称结论，现在**仅在可观测情形成立**——而这恰好是作者自己搭的闭环。附录 A 把作者最硬的一根柱子抽走了。

- **预判辩护**：作者会答——可观测性边界是诚实刻画的真实限制；fail-open 方向已被明确报告；v2 与 degrade_all 是权衡而非占优，这正是附录 A 修正后的准确表述，我们没声称 v2 在所有情形占优。

## 「全做通也不算贡献」论证

**成立，标 Critical。**

假设作者补齐一切：数字全漂亮、消融全成功、原生引擎与 port 一致、真实系统（Nextcloud/Gitea）兑现、跨模型独立复核通过——本文**仍不构成 JISA 期刊级贡献**。理由：

1. **重述后的贡献 = 原作者已知局限的复读。** 贡献锚点"GUI 提供性不能代理授权状态"直接来自 MST-wi 原文定义，且原作者**自己写了**"roles–resources 映射 not always available"（已核实 `mstwi_paper_text.txt:73-74`）。你做的是把原作者承认的局限，用 2 端点玩具再演一遍。JISA 要求"说了原作者不知道的事"，而你在说的，原作者已经说了。

2. **"缺口"被你自己的 30 行代码补上，故不是范式边界而是实现缺口。** `shares_of`/`can_access` 就是那条"缺失的授权状态谓词"，S3 上恢复率 1.00。一个被作者亲手补上的缺口，不能支撑"范式丧失可判定性"的泛化论断。

3. **"修正机制"只在作者自造的数据可见闭环内成立，且在不可观测时引入更严重的假确证（fail-open）。** 这把"MR 不行就查授权库"包装成"方法的边界刻画"，实质仍是第五轮已判的"跳出 MR 问政策"。附录 A 还自拆了"v2 优于一律弃权"的占优论证。

4. **体量使泛化无据。** 证据底座 = 2 条手工挑选的授权 MR（MR-002/004，且为语义移植非原生；作者 D6 自认仅 2/4 条授权 MR 被移植）跑在 2 端点、3 文档的玩具上；MST-wi 是 76 条 MR + Jenkins/Joomla 真实应用。从"2 条 MR 在我造的 2 端点上误触发"跳到"现有变形测试的授权 MR 丧失判定力"（中心问题、§0 全称陈述），中间无任何真实应用支撑，且原生引擎未跑。

5. **即便作为负面结果也偏弱。** 被"证伪"的期望（"不含状态谓词的 MR 在含对象共享的 app 上会误报/漏报"）是显然的；加一个状态谓词 FP/FN 即归零，说明这是**缺一个谓词**，不是**范式硬边界**。

结论：即便全可复现，本文最大可成立贡献 = "MST-wi 授权 MR 的判定依赖 GUI 提供性而非授权状态，这是一个已知局限；我们在 2 端点玩具上演示了其误差方向，并给出一个状态谓词补丁"。这是一则**目录缺口 + 补丁笔记**，非 JISA 方法论文。
