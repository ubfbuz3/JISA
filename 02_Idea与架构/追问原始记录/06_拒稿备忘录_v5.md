## 设计 1：E3「原理上不可表达」形式化命题（C2 / §2.1–§2.2）

- **steel-man**：这是全文唯一试图从「经验观察」升格为「原理定理」的部件，也是把审稿人「E3 显然不可表达、太 trivial」挡回去的护城河。最强形态是：用归谬证明 MR 框架若想表达 E3 例外 `h(i,o)`，就必须把 `P(i,o,read)`（授权政策本身）写进 precondition，得到「若 i 无权访问则 i 无权访问」的重言式，故 E3 在 MR 范式内不可表达。这把「MST-wi 没写对象谓词」从疏漏提升为「语言表达力决定的硬边界」，是论文最像「理论贡献」的一笔。

- **攻击**：
  1. **命题的前提被论文自己的 §1.2 当场推翻。** §1.2 谓词表明确列出 `cannotReachThroughGUI(user, url)`（GUI 可达性类，二元，第一元主体、第二元 url/对象）。url 标识被访问对象，这正是一个**主体×对象**谓词。论文在 §2.1 却断言「E3 = 主体×对象、元数 2、原理上不可表达」，并在 §1.3 把对象级谓词零命中核验为 `ACL/belongsTo/canAccess/hasAccess/granted/owner/ownership` 全部缺席——**唯独把 `cannotReachThroughGUI(user, url)` 靠改标签（GUI 而非对象级）排除在「对象位置」之外**。这是用分类魔术制造「对象位置零命中」：一个带对象参数的谓词被改名后就不算对象谓词。C2 证明的第一步「MR 语言没有对象位置」在自己的展品面前为假。
  2. **实验本身证明 MR 的判定就是被这个主体×对象谓词决定的。** `mstwi_mrs.py:243-252` 用 `GET /doc` 列举端点建模 `cannotReachThroughGUI`；`app.py:112-124` 的 `visible_in_listing` 把 listed 共享判为 GUI 可达。`SUMMARY.md` 附表显示：listed 时该谓词为假 → MR 不适用 → 真 BOLA 被漏报（FN）。即 MR 在对象访问上的命运，正由这个主体×对象谓词因果地决定。论文管它叫「GUI 谓词」不改变事实：**一个主体×对象关系正在做授权裁决**。
  3. **作者自己的 Boundary-aware 探测器构造性地反驳了 C2。** `engine.py:117-119` 的 `shares_of(doc_id)` 返回 `(doc, grantee, permission)`——一个主体×对象×权限的授权谓词。作者亲手写出并运行了「能表达 E3 的 MR 前置」（v2 权限层级匹配）。C2 声称「原理上不可表达」，而论文附录的探测器代码就是反例：该谓词平凡可写。
  4. 因此 C2 若诚实重述，只能降为「MST-wi 的目录未包含一条*授权语义*的对象谓词」——这是**文献核查观察**，不是原理定理，且连这观察都被 `cannotReachThroughGUI` 的存在削弱了（它至少携带对象位置）。

- **预判辩护**：作者会答——`cannotReachThroughGUI` 是 GUI 可达性谓词，不是授权谓词，故不表达 `h(i,o)`；检测器里的 `shares_of` 是「我们自己的修正方案」，恰好说明 MST-wi 原生语言缺它。

- **辩护评分**：**1/5 → 直接推翻，不得撤火。** 该辩护救不了 C2：(a) 归谬证明的前提「语言无对象位置」被 §1.2 自己的展品证伪，归谬从第一步就崩；(b) 实验数据表明该「GUI 谓词」实际承担授权裁决，标签之争不影响其主体×对象实质；(c) 作者自己的修正代码构成对「不可表达」的构造性反例。处置：C2 必须改写为观察性陈述（「MST-wi 授权 MR 未含授权类对象谓词」），**删除「原理上不可表达 / 否则退化为重言式」的定理式措辞**；否则 §3 命题与 §1.2 自相矛盾，构成硬伤。

## 设计 2：构造式真值驱动的 E3 探测（§2.4 / Boundary-aware）

- **steel-man**：这是论文从「纯批判」翻身为「有可执行修正」的关键，也是 JISA 接受与否的生死线。最强形态是：我们**主动调用共享 API 创建共享**，于是「对象被谁共享」是测试框架亲眼产生的构造式真值，不是从实现制品推断的政策；据此在 MR 触发后加一步 E3 探测，有共享记录则降级 `indeterminate`、无则升级 `violation-proven`，从而在不靠弃权的前提下恢复可判定性（`degrade_all` 检测力 0 已反证「不是一律弃权」）。这把「oracle 问题」从哲学抱怨变成可跑的两步协议。

- **攻击**：
  1. **三人合一的循环验证。** 同一作者写了三样东西：MR 移植语义（`mstwi_mrs.py`，故意不含对象位置）、被测系统（含 E3 共享语义的 `app.py`）、真值（`engine.py` 的 `share_log` + `can_access`）。「100% FP」不过是作者观察到「自己移植的、删掉对象位置的 MR」在自己造的、带对象共享的 app 上必然误触发。结论在构造时已被锁定，这不是发现边界，是**作者给自己搭的舞台演了自己写好的剧本**。
  2. **E3 探测只在「作者即共享者」的闭环内有效，闭环一破即归零。** `shares_of` 的数据源是 `client.share()` 写下的 `share_log`（`engine.py:106-119`），而 `share_log` 只记录**测试框架自己调用共享 API 的那次**。真实世界的合法对象级访问来自：管理员后台配置、历史委派、OAuth 第三方共享、组织策略——**没有一条由测试框架创建**。一旦合法共享来自框架未创建的通道，`share_log` 为空，E3 探测读不到任何记录，结果退回原始 MR 的误报（FP），「恢复可判定性」彻底失效。论文 §4.1 承认 crAPI/VAmPI 无共享语义、必须自建，但**从未实验覆盖「框架外创建的合法共享」这一最关键情形**——而这恰恰是 E3 探测本该证明适用的唯一真实场景。
  3. **唯一的外部恢复路径就是承认 MR 做不到、去查政策本身。** 当共享确实来自框架外，要恢复判定只能去查 app 的授权状态（`GET /doc/{id}/shares` 或政策服务），这正是 `P(i,o,read)`——§2.2 刚说它在 MR 内不可表达、必须退出的那个政策谓词。所以 Boundary-aware 的「修正」实质是：**MR 不行就跳出 MR 去问政策**。这不是对 MR 范式的贡献，是作者亲手指认 MR 在该处无解。把「跳出 MR 调政策接口」包装成「MR 边界的可执行修正」是措辞套利。
  4. **统计底座是 2 条 MR 的切片，不是 2 个样本。** `FP_E3=1.00` 来自 `V-E3-vuln0-unlisted @ S3` 的 `2/2`（`SUMMARY.md` Block 2），即 MR-002 与 MR-004 两条均触发；而同表 listed 配置该格为 `0/2`。所谓「显著升高」只在作者选定的 unlisted 可见性下成立，诚实聚合（M4）特异性仅 `0.889`。论文修辞压在 `1.00` 切片上，掩盖了 listed 场景 FP=0 的事实。

- **预判辩护**：作者会答——我们明确定位是「受控实验测可控性，不外推真实覆盖率」；E3 探测的适用前提本就是「共享操作可观测」，论文 Limitations 已写；`degrade_all` 检测力 0 已证明不是弃权；v2 代价率 0 证明探测有真实增益。

- **辩护评分**：**2/5 → 继续加压。** 定位声明救不了致命伤：论文把「受控」当作豁免，却用受控结果支撑「MR 范式丧失辨识力」这一**泛化**论断（§0 中心问题、§5 对照表均对「现有变形测试的授权 MR」做全称陈述）。受控系统的变量是作者人为注入的，泛化结论无支撑。「共享操作可观测」这一前提在真实 API 上恰好最难满足，而论文恰恰没测最难满足的情形。加压方向：要求补做**框架外创建的合法共享**对照（预置管理员/第三方共享的 DB 种子，测试框架不调用 share API）；若 Boundary-aware 在该情形下恢复率跌回 0，则 C3 的「恢复可判定性」只在自造闭环内成立，全文降级为玩具演示。

## 设计 3：listed / unlisted 两面性发现（实验「关键发现」）

- **steel-man**：这是作者自认「超出原方案预期、最有价值」的发现，也是把纯逻辑结论变成「实践中真有两种错误、且可知何时发生哪一种」的升级。最强形态是：MST-wi 的特异性 99.81% 建立在一个未言明前提上——GUI 可达性模型与真实授权一致；当对象级授权不经 GUI（unlisted：分享链接/API scope/委派）时该前提破裂，MR 在误报与漏报间二选一：unlisted → 前置条件成立 → 误报；listed → 前置条件不成立 → 真 BOLA 漏报（1 条）。这比「E3 不可表达」更强，因为它说清了限制会**产生哪两种、何时产生哪一种**错误。

- **攻击**：
  1. **两面性完全是作者自己代理语义的产物，不是 MST-wi 的属性。** `app.py:112-124` 的 `visible_in_listing` 被作者定义为「仅当 `share_visibility=='listed'` 时共享对列举端点可见」；`mstwi_mrs.py:243-252` 用该列举端点建模 `cannotReachThroughGUI`。于是 unlisted→列举不含→谓词为真→触发→FP；listed→列举含→谓词为假→不适用→FN。这是作者**建模选择的直接推论**，与 MST-wi 原生 GUI 爬虫毫无关系——而论文从未跑过原生引擎（Maven 缺失，`EXPERIMENT_PLAN.md` 环境约束）。那句「MST-wi 特异性 99.81% 依赖于未讨论前提」是**对未运行之物的外推**，无任何 native 证据。
  2. **这个「发现」恰恰证明 C2 是假的。** 论文说 E3（主体×对象）原理上不可表达；可两面性的全部因果机制正是一个**主体×对象谓词**（`cannotReachThroughGUI(user, url)`）在决定对象访问裁决。作者在同一篇里一边称「主体×对象不可表达」，一边把「主体×对象谓词决定成败」当作新发现——自相矛盾。要么 C2 假（该谓词存在且起作用），要么两面性发现假（它没在说主体×对象的事）；二者不能同真。
  3. **两面性坍缩为一个已知 truism。** 「若用 GUI 列举建模授权，则列表中未见的对象看起来像违规、列表中的对象看起来合规」=「代理 oracle 的正确性等于代理的完备性」。这是 oracle 文献的常识，不是对 MST-wi 的新诊断。论文把它包装成「比不可表达性更强的发现」，实质是把「你的代理不完整」重述了一遍。

- **预判辩护**：作者会答——我们双向报告了 gui_blind/gui_aware，结论方向一致即稳健；listed 漏报那条是诚实报告的 FN，正是「判定外包给 GUI 模型」的证据；我们没声称测了原生 GUI 爬虫，只说代理语义下如此。

- **辩护评分**：**2/5 → 继续加压。** 「双向报告」只说明作者的两个代理变体结论同向，不说明结论关于 MST-wi。诚实报告 FN 值得肯定，但不能把「作者代理的缺陷」升格为「MST-wi 的未言明前提破裂」。更糟的是它与 Design 1 的 C2 自咬。加压方向：要求明确指出「两面性来自本文代理语义，非 MST-wi native 行为」；若无法跑原生引擎证明 native 同样两面，则该发现只能写为「我们移植的 MR 在自建代理下表现」，不得外推 MST-wi 的 99.81%。

## 「全做通也不算贡献」论证

**成立，标 Critical。**

假设所有数字漂亮、所有消融成功、恢复率 1.00 代价 0.00、native 引擎与 port 一致、独立复现通过——论文仍不构成 JISA 期刊级贡献。理由：

1. **「边界」是被构造出来的，不是被发现的。** 作者手工从 MST-wi 移植了 2 条 MR（故意不含对象位置），又手工造了一个带对象共享的 2 端点系统，再手工定义真值。在这个三人合一的闭环里，「MR 不含对象位置 → 在含对象共享的 app 上误报」是**定义即真的重言式演示**，不是对「变形测试范式」边界的实证。把对一条自删对象位置的 MR 的观察，泛化为「现有变形测试的授权 MR 丧失辨识力」（§0、§5 全称陈述），是规模欺诈。

2. **修正方案在真实场景为零适用。** E3 探测依赖 `share_log`，而 `share_log` 只含测试框架自己创建的共享。真实合法共享来自框架外的通道（管理员、委派、第三方）。一旦如此，探测读空、恢复失效；唯一退路是去查 app 的授权状态——即 §2.2 说「不可表达、须跳出」的政策谓词 `P(i,o,read)`。故「修正」=「MR 不行就问政策」，是亲手指认 MR 无解，不是对 MR 的贡献。

3. **「不可表达」定理本身站不住（见 Design 1）。** 论文自己的谓词表与探测器代码都含主体×对象谓词，C2 在前提层自相矛盾。一个自相矛盾的定理不能支撑贡献。

4. **体量差使泛化无据。** 证据底座是 2 条手工挑选的授权 MR（MR-002/004，且为移植非原生）跑在 2 端点、3 文档的玩具上；MST-wi 是 76 条 MR + Jenkins/Joomla 真实应用。从「2 条 MR 在我造的 2 端点上误触发」跳到「MR 范式在 E3 上丧失可判定性」，中间无任何真实应用支撑，且原生引擎未跑。

5. **即使作为负面结果也偏弱。** 负面结果有价值的前提是它证伪了一个非平凡期望。这里被证伪的期望（「不含对象位置的 MR 在含对象共享的 app 上会误报」）是显然的；加上一个对象谓词 FP 即归零，说明这是**缺一个谓词**，不是**范式硬边界**。

结论：即便全可复现，本文最大可成立贡献 = 「MST-wi 授权 MR 未含授权类对象谓词；我们在 2 端点玩具上演示了一种误报，并说明加对象谓词可修」。这是一则目录缺口笔记，非 JISA 方法论文。
