## 1. 逐条答辩

### D1 · `userCanRetrieveContent` 与"对象级谓词零命中"

**裁决：承认（且加重）**

我复核了 catalog 原文与词频：

| 谓词 | 出现次数 |
|---|---|
| `userCanRetrieveContent` | **54** |
| `cannotReachThroughGUI` | 8 |
| `isSupervisorOf` | 7 |
| `isAdmin` | 2 |
| `notTried` | 53 |
| `owner` / `ownership` / `delegat` / `canAccess` / `hasAccess` / `ACL` / `belongsTo` / `granted` | **全部 0** |

并且它不是只作 oracle 项——它**作前置条件**，例如 `MR CWE_298_599`（catalog line 1192–1193）：

```
IMPLIES(
   isLogin(action) &&
   notTried(...) &&
   userCanRetrieveContent(action.user, Output(Input(1), pos)) &&     // ← 前置条件
   CREATE ( Input(2), Input(1) ) && ...
```

`userCanRetrieveContent(action.user, Output(Input(1),pos))` 的签名是 **（主体, 对象）**。所以：

- ❌ **"对象级谓词零命中" = 假命题。** v5 §1.2 的分类与 §2.2 的一行打发，都不成立。撤回。
- ✅ **我的错误是方法论层面的**：我做的是**"授权词汇表"词频检索**（`owner`/`ACL`/`canAccess`/`granted`），
  得出"零命中"。但该 DSL 表达对象级概念时用的是 **GUI 词汇**（`retrieveContent` / `reachThroughGUI`）。
  **词表检索不能替代读谓词签名。** 这条要写进方法论教训。
- ⚠️ **但对 A 路的推论我部分保留**：`userCanRetrieveContent(u, o)` **不是授权谓词**。
  它判定的是"该内容能否从 GUI 取到"，不是"该主体是否被授权"。我在 §2.2 的判断本身是对的，
  错的是**分类与那个全称断言**。

**修正后的准确陈述（拟写入论文）**：

> 该 DSL 的**对象级**谓词**全部是「GUI 提供性」派生的**（`userCanRetrieveContent` ×54、`cannotReachThroughGUI` ×8）；
> **授权状态派生的对象级谓词为零**（`owner`/`ownership`/`delegat`/`canAccess`/`ACL`/`granted` 全 0 命中）。

这是一个**窄断言**，但它可证伪、可复核，而且——见 D5——**正是论文真正要打的靶子**。

### D2 · "误报是自己关掉谓词造出来的"

**裁决：一半承认（承认呈现缺陷），一半用数据反驳**

我复核了原始数据（`raw_matrix.jsonl`，`precond=raw`）：

| 配置 | `gui_mode` | S3（授权**正确**，有共享） | S5（只读共享下的**写**越权） |
|---|---|---|---|
| `V-E3-vuln0-listed` | **aware** | 0/2 | 0/1 |
| `V-E3-vuln0-listed` | blind | **2/2 FP** | 0/1 |
| `V-E3-vuln0-**unlisted**` | **aware** | **2/2 FP** | 0/1 |
| `V-E3-vuln0-unlisted` | blind | **2/2 FP** | 0/1 |
| `V-E3-vuln1-listed` | **aware** | 0/2 | **0/1 FN** ❌ |
| `V-E3-vuln1-listed` | blind | 2/2 FP | 1/1 |
| `V-E3-vuln1-unlisted` | aware | 2/2 FP | 1/1 |

**反驳部分**：`V-E3-vuln0-unlisted @ gui=aware` —— GUI 谓词**生效中**（`aware` 会去读访问者的列举端点），
S3 仍然 **2/2 触发**。所以 FP **不是**"关掉谓词造出来的"，而是**被测系统的通道属性**（共享对访问者的 GUI 不可见）驱动的。
`unlisted` 是**系统的属性**，不是我方法的开关；真实世界对应分享链接、API scope、委派。

**承认部分**：A 路这半边对——**`gui_mode=blind` 不是 MST-wi 的部署形态**（它会爬 GUI）。
我把 `FP_E3=1.00` 做成头条数字而**隐藏了 `gui_mode` 这个轴**，这是**呈现缺陷**，必须改。

**并且——真正的结果比单一数字强得多**：4 格里 3 格 FP；**唯一没有 FP 的那一格（`listed+aware`）同时产生了 1 条 FN**。
所以那不是"谓词有效"，而是**谓词在用 FP 换 FN**。这正是 v5 的"两面性"，但 v5 的表格没把它讲成"同一枚硬币"。

**修正**：弃用单一 `FP_E3`，改报 **2×2 网格**（GUI 可见/不可见 × 授权正确/越权），
并把 `gui_mode` 作为**显式实验变量**在正文声明。

### D3 · "E3 探测是循环论证，只是换了个马甲"

**裁决：承认覆盖缺口，不接受"循环"的定性**

**承认**：我复核了场景构造——**S1–S5 全部**的共享都是**测试框架自己调 `share()` 创建的**。
**实验里没有任何一个场景测"预存共享"**（管理员配置、历史委派、第三方分享）。
所以"恢复率 1.00"是**封闭世界构造的产物**，不是普遍结论。这是**真实的实验设计缺口**，我漏了。

**不接受"循环"**：v3 的病是"政策谓词 `forbidden(i,o,e)` **没有独立来源**"。
v5 的探测用的是"**我执行了 share 操作，并观测到 200**"——这是**独立于被测策略谓词**的构造式事实。
它不是从实现制品反推政策。所以定性应是 **"证据可信但不完整"**，不是"循环"。

**准确表述**：探测有效范围 = **"共享操作对测试框架可观测"**。
超出这个范围（预存 + 不可观测共享），探测退化为"无 E3 → 升级 violation-proven" → **误报原样保留**。
⇒ **Boundary-aware 方法自身有边界，且这个边界可测。** 这不是要藏的弱点，这是论文该报的第二层结果。

### D5 · "全做通也不算贡献"（B 路标 Critical）

**裁决：接受为 Critical —— 但接受的是"现措辞下成立"，并给出重构**

**若维持现措辞**（"MST-wi 缺对象级谓词"）：B 路对。
两名审稿人一句话就能推翻（谓词明明有 54 处），且贡献确实只是"少了一个谓词的笔记"。**这种形态不该投。**

**但我找到了一个更强的立论锚点，而且它不是我的解读，是 MST-wi 自己的定义**（arXiv:2208.09505 原文）：

> "...an MR to spot bypass authorization schema vulnerabilities should ensure that a Web system returns
> **different responses to two users when the first user (User-A) requests a URL that is provided to her by the GUI**
> (e.g., in HTML links) while **the second user (User-B) requests the same URL, which is not provided to her by the GUI**."
> ...
> "If the output for the two users is the same, User-B can access the same page accessed by User-A instead of
> receiving an error message, **which is not the functionality exposed by the user interface**."

同一段里它还自陈：*"we need a mapping between roles and resources, **which is not always available**"*。

**这段原文把整件事说穿了**：
1. 该 MR 的判定标准是 **UI 一致性**（"GUI 提供了吗" / "UI 的功能是否如此"），**不是授权状态**；
2. `userCanRetrieveContent` / `cannotReachThroughGUI` 是这一标准的**可执行形式**；
3. 作者自己承认"角色—资源映射不可得"，**其替代方案就是退回 GUI 提供性**。

**在这定义下，我的实验结果是它的忠实实例化，而不是对稻草人的攻击**：

| 系统的通道属性 | MR 的判定 | 真值 | 结果 |
|---|---|---|---|
| 共享对访问者 GUI **不可见**（分享链接 / API scope / 委派） | "B 拿到了 GUI 没给她的 URL" | 合法 | **FP** |
| 共享对访问者 GUI **可见** | "B 拿到的 URL 是 GUI 给过她的" | 越权（只读共享下写） | **FN** |

⇒ **贡献重述**：证明「**GUI 提供性不能代理授权状态**」，并给出误差方向**可由通道可见性预测**的机制、量化两侧、给出有边界的修正。
这仍然属于"限制研究"体裁，**机制新意薄**——但它是**可证明、可量化、有构建性修正**的，比"缺一个谓词"强得多。

**Novel 如实给 3（重述后）／2（维持现状）。** 若评审不接受重构，这篇不该投。

## 3. 认为对手方**过严或范畴错置**之处

### 3.1 A 路把"GUI 可达性谓词"等同于"授权例外处理"

A 路称 `userCanRetrieveContent`「正是 E3 的定义」。**这是范畴错置。**
E3 的定义是"**主体×对象的显式授权**"（`h(i,o)`，政策谓词）。
`userCanRetrieveContent(u,o)` 是"**该主体能否从 GUI 取到该对象**"（通道谓词）。
两者**在外延上相交**（GUI 可见的共享对象两个都为真），但**内涵不同**，且**在通道不可透明时背离**——
这正是我实验测到的 FP/FN 两方向。把它们等同，会得出"E3 已被处理"的错误结论；
而 S5 那一格的 FN 恰恰证明"GUI 可见"≠"被授权"。

### 3.2 A 路用 `listed` 格的 FP=0 论证"对象级判定能消解误报"

该论证据不完备：**同一格**（`listed+aware`）在 S5 上有 **1/1 FN**。
请对手方给出一个配置，使该 MR 在「S3 合法共享」与「S5 只读共享下的写越权」上**同时正确**。
若不存在（我实测两格构成互补的错误集），则"谓词有效"不成立，正确表述是**"谓词在两种错误之间二选一"**。

### 3.3 B 路要求"证明不是为结论造结论"——这个举证责任设置本身不成立

受控实验的正当性标准是**机制可控性与可反驳性**，不是"系统必须不是我造的"。
真正的举证责任在我这边的部分我接受（补真实系统）；但把它上升为"构造即无效"，则任何受控实验都无法通过。
