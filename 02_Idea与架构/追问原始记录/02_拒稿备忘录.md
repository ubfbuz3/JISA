## 拒稿备忘录 · 独立审查

审查边界：仅依据 `idea_v3.md`、`idea_v2.md` 与 `availability.md`。文中未被这三份材料证实的工具能力、漏洞清单完整性、数据集属性及数值，一律不替作者补证。

### 一、三处核心设计的攻防

#### 1. 立论基石（fault 306 引用）

- steel-man: fault 306 的原文明确承认：访问策略可以任意复杂；没有详细形式化规格时，自动判定 BOLA/BFLA 很困难；启发式至多标出“高度可疑”的情形。因此，将“端点可达性”与“是否违反授权政策”区分开，确实是一个真实问题。作者进一步把问题表述为“缺少把请求行为映射到授权规格的桥梁”，而非泛称现有 fuzzing 不够好；这是比 v1 的 LLM 新颖性主张克制得多的定位。
- 攻击: 原文证明的是**需要形式化访问策略**，不是“从 OpenAPI、路由、中间件、ORM、SQL 谓词和 role 字面量自动抽出的 clause 就是该策略”。这两件事之间正是论文尚未证明、却借 fault 306 偷换掉的关键一步。复杂政策的反例已在引文中出现：管理员可以合法访问他人资源；材料还承认跨服务工作流、状态条件、检查存在但错误等情形。现有实现制品最多显示已部署的检查或数据关系，不能区分“安全策略允许共享”“策略遗漏”“实现错误地放行”。故 C1 的“规格缺口”即使量到 OpenAPI/启发式覆盖率，也只说明**两类表示不覆盖人工标注的 clause**；它不说明该 clause 是真实授权规范，更不推出自动生成的 clause 能填补 fault 306 所说的缺口。

  更严重的是 L0 的真值仍是“人工标注 clause（双人 + 仲裁）”。若人工能据源码、业务语义或外部知识裁定 clause，实验量到的是标注者的政策模型与 OpenAPI 的差，而不是自动方法获得了原本缺失的正式规格。若标注者只准看方法输入制品，则无从证明其标注比自动抽取更接近真实政策。两种解释下 C1 都不能支撑“补上规格”的贡献。
- 预判辩护: 作者会说：论文已放弃“证明开发者意图”，仅构造“有证据支撑的候选授权契约假设”；clause 必须有 span、类型检查和双证据门控，不能通过者记为 unknown，因此不会把 LLM 猜测升级为告警。
- 辩护评分: 2/5 ⇒ 继续加压。该回答把问题从“规格”改名为“候选假设”，却仍在摘要式贡献中称“有规格依据的可机检裁决”。span 证明文本出处，不证明该出处蕴含访问许可；双证据只降低无根据候选的数量，不验证候选的政策真值。加压方向：要求作者在不接触运行时结果的前提下，给出独立、预先冻结且逐 clause 可审计的政策真值来源；若做不到，C1 只能写成“制品间证据缺失的描述性统计”，不得称为规格缺口或补位。
- 处置: 继续加压。拒绝接受把 EvoMaster 的“需要 formal specification”改写为“自动证据抽取已提供 formal specification”。

#### 2. 核心仪器（VAmPI 孪生）

- steel-man: `vulnerable=0/1` 提供相同代码、OpenAPI、端点与数据库结构、仅改变漏洞开关的配对实例。相较作者自行注入且可能混入其他改动的 L3，若一个裁决在 :5002 命中并在 :5001 静默，它至少是强得多的受控行为差异证据。材料也没有把 secure 模式神化：它明确引用官方提示，`vulnerable=0` 仍可能保留漏洞，并要求实验前冻结排除清单。
- 攻击: 这不是干净的“阴性对照”，而是一个**已知不完全安全的对照加一份由作者决定的排除清单**。在这种设定下，“:5001 静默”不能等价于无 FP：作者可以把触发点归入排除清单，而材料没有给出排除规则、枚举边界、冻结时点相对于工具开发/调参的隔离，或排除项的独立审计。反过来，`:5002 命中` 也不能证明检出的是 BOLA；VAmPI 官方 9 项清单包含 BOLA 之外的类别，且 L1 官方清单只是教学挑战、不能当完整分母。一个在两端都触发的真实缺陷、非 BOLA 缺陷或端点行为变化，都会使“静默率”和“FPR”失去可解释性。

  更根本的是，孪生只验证该靶场在一个开关下的**差异敏感性**，没有验证方法对真实政策的正确性。若 clause 恰好拟合 VAmPI 的实现开关，方法会显得准确；这无法表明它解决了复杂共享、角色例外和跨应用策略。L2 可以是回归测试仪器，不能承载“官方安全孪生上的 FPR”或 C2 的泛化论证。
- 预判辩护: 作者会说：排除清单将在实验开始前预注册并公开；L1–L4 分层、禁止合并总分，且作者已承认 L2 安全模式“不完全干净”，所以不会把它当作全部真值。
- 辩护评分: 3/5 ⇒ 继续加压。预注册能阻止事后移动边界，不能使边界正确；公开的作者自定排除表也不能证明余下端点安全、排除项穷尽或问题类别与 BOLA 对齐。分层报告避免了加权混淆，却不改变每层指标的识别条件不足。加压方向：将 L2 指标降格为“对该版本、该冻结端点集的配对行为一致性”，逐项报告 `5001/5002` 的原始响应和人工类别；不得称 FPR，除非有独立且完备的端点级 BOLA 真值。
- 处置: 继续加压。VAmPI 可保留为工程回归测试，不能作为 C2 的核心效度仪器。

#### 3. 核心方法（分层 verdict + 状态校准）

- steel-man: v2 已诚实识别单一“响应等于 self-success”规则的脆弱性，并以四层结论取代它。`confirmed-read` 要求受害者对象稳定唯一字段，`confirmed-write` 要求受害者对象状态可回读，`likely` 和 `inconclusive` 不计入主指标；幽灵对象、攻击者自有对象和重复执行能排除一部分不存在对象、异步、限流或偶然 200 的噪声。将 state-unreachable 报告而非静默删除，也是可复现实验的必要改进。
- 攻击: 该校准证明的是“请求访问到了受害者对象/改变了它”，不是“访问违反了授权”。只要 API 的真实政策允许协作、代理、管理员或公开共享，`confirmed-read`/`confirmed-write` 的所有技术条件均可满足，结论仍可能是合法的。幽灵对象只区分“对象不存在”与“对象存在”，自有对象只区分“可访问自身”与“可访问他人”；二者都不提供“他人对象应被拒绝”的政策证据。于是方法把 BOLA 的规范性判定降解为跨账户可观察性，而 fault 306 正在警告这种降解不成立。

  形式化 sketch 还把 `OwnerFields` 视为可机检输入，但其来源是 ORM 归属字段与 SQL `WHERE` 的 owner 列。所有权字段是数据关联，不是禁止共享的授权规则；缺少 owner 谓词也不能证明缺少检查，存在 owner 谓词也不能证明检查在当前动作上生效。对读操作，“出现稳定唯一字段”可确认数据流，却无法确认字段属于受害者、不是共享副本或查询投影；对写操作，“可回读状态改变”可确认副作用，却无法确认攻击者无被授予的写权。分级降低语言强度，却没有补上 `forbidden(i,o_A,e)` 这个定义 BOLA 所必需的谓词。
- 预判辩护: 作者会说：clause 与证据图正是 `forbidden` 的近似来源；无双证据或不稳定对照时一律 `inconclusive`，并不把所有跨账户成功判为 confirmed。作者也可将 LLM 完全降级，终局裁决是确定性的。
- 辩护评分: 2/5 ⇒ 继续加压。确定性只意味着可重复执行，不能使未验证的近似成为真值；而“候选 clause”若不能证实禁止关系，恰好不能补足 `forbidden`。高门槛可能减少输出，却可能系统性地把共享政策误报为 confirmed，或把难例转入 inconclusive 并仅在可成功的靶场上报告。加压方向：必须设计含**合法跨账户共享/管理员访问**且与 BOLA 在响应、对象存在性、自有对象成功上完全相同的正交对照；若系统仍判 confirmed，C2 被直接证伪；若需人工添加政策，论文必须承认其 oracle 依赖人工规格。
- 处置: 继续加压。当前 verdict 是“跨账户对象效果确认器”，不是 BOLA 判定 oracle。

### 二、构造性反例

#### C1：规格缺口可量化

用什么数据 ⇒ 选取 L0 已列的 crAPI、VAmPI 和经逐一核实后纳入的多账户 WFD SUT；在每个受保护端点之外，专门选取一个真实允许的协作、管理员或资源共享场景（若这些材料中找不到该场景，则此 C1 的“真实 API”范围本身应标为待核实）。由独立标注者在不知道系统输出的条件下，分别写下：访问允许条件、禁止条件、证据来源和“不足以判定”。

什么操作 ⇒ 将同一端点的 OpenAPI、EvoMaster 启发式覆盖和作者的证据图/clause 输出，与独立标注的允许/禁止条件逐 clause 对齐；特别统计作者方法把“允许共享”编码成 owner-only 禁止条件的比例，以及标注者只能写“不足以判定”的比例。

看到什么算推翻 ⇒ 若所谓“无法由 OpenAPI/启发式表达”的 clause 中，存在非偶发的一组只能由业务政策判断、而作者输出却稳定给出 owner-only 禁止关系，或独立标注无法从允许输入中判定，则“规格缺口可量化且被自动证据补位”被推翻；至多剩下“若干制品未表达人工选择的 clause”。

#### C2：状态校准把可疑升级为分级结论

用什么数据 ⇒ 在 L3 的容器化 API 中建立成对端点/版本：两者均有攻击者访问受害者对象、攻击者自有对象成功、幽灵对象拒绝和稳定响应；一者实现明确允许的共享或管理员授权，另一者省略该授权检查形成 BOLA。发布两者的版本 pin、mutation diff、账户/对象创建脚本及独立政策标签。

什么操作 ⇒ 在不向方法暴露“共享合法/访问违法”标签的条件下，对两者运行完全相同的 clause 抽取、producer-consumer 状态构造与四层 verdict；按读、写分别比较 verdict。

看到什么算推翻 ⇒ 若合法共享端点得到 `confirmed-read` 或 `confirmed-write`，则“confirmed”并非 BOLA 确证；若为避免此错误必须提供人工共享/角色策略，C2 的“自动升级”被推翻，结论应改为“在外部策略输入下校准运行时证据”。若两者都只报 inconclusive，则其“把可疑升级”的效用主张同样不能成立。

#### C3：可复现的 BOLA 评测协议

用什么数据 ⇒ 使用 L1 crAPI/VAmPI、L2 孪生、L3 构造集、L4 经核实的 WFD 子集；冻结每一层的版本 pin、端点清单、账户种子、排除表、请求预算、模型 ID/提示/温度、重试和响应规范化规则。另准备一份不向复现实验者暴露的端点政策标签与分类准则。

什么操作 ⇒ 由独立复现者从空环境按仓库说明运行两次，并由第二组审计者在不知道系统 verdict 的情况下审查：端点是否能建出两账户同型资源、排除表是否足以解释 secure 端触发、每一 confirmed 是否确实违反隐藏政策标签。比较两次的样本集合、状态可达率、verdict 和人工审计结论。

看到什么算推翻 ⇒ 若同一固定版本因初始化、ID、异步或选择规则产生不同纳入样本/结论，或 confirmed 不能由独立政策标签确认，或 L2 的“FP”必须依赖临时扩张排除表，C3 被推翻。仅能重放 HTTP 轨迹不等于可复现 BOLA 评测；必须重放真值生成与裁决边界。

### 三、最致命的一种可能

**Critical：即使所有计划实验均跑通、数字均好看，论文仍可能没有可接受的 JISA 贡献。**原因不是实验规模，而是研究对象定义错误：BOLA 是“未获授权地访问对象”，其中“未获授权”是政策谓词；本文的确定性 oracle 只从实现制品和四次请求中建立对象存在、跨账户访问与状态改变。它没有独立获得或验证政策谓词。候选 clause 的 span、类型检查、双证据和 LLM 降级都只能证明该假设可追溯、可重复，不证明它为真。VAmPI 的双实例只能显示开关导致行为差异；L3 的注入真值只能证明作者写入的缺失检查能被作者的测试发现；L4 又无 BOLA 真值。因而再高的 precision、静默率和重放率也可能只是“对作者所选实现模式与作者所定标签的一致性”。这是一套很好的测试工件/回归框架，但不是证明 BOLA 判定正确的新安全方法。若没有独立、可审计的授权政策真值与含合法跨账户访问的反事实测试，论文的中心贡献是循环验证，不能以 oracle 创新进入 JISA。

### 四、退守线

最低可接受的 claim 边界只能是：**一个面向已知或外部给定授权策略的、可复现的多账户 API 行为测试与证据记录框架。**它可声明：在冻结的应用版本、账户脚本、对象映射、响应规范化和**人工/官方提供的端点级授权期望**下，框架能重放跨账户读写行为，并把可观察到的对象泄露、状态改变、不可达和不确定情形分开报告。

它不得声明或暗示：自动从实现恢复正式访问策略；把 EvoMaster 的“可疑”自动升级为 BOLA 确证；VAmPI secure 模式给出一般 FPR；L1/L4 给出完整 recall；或其自建 mutation 证明对现实 API 的检测有效性。若没有外部政策真值，`confirmed-*` 必须改名为“证实发生跨账户对象读取/写入”，并且不等同于漏洞。

### 五、分级清单

**Critical**

- C2 的 `confirmed-read/write` 缺失“该访问被政策禁止”的独立证据；跨账户可观察性被误当作 BOLA。
- C1 用 fault 306 所要求的 formal specification 反推“自动抽取 clause 已补上规格”，构成未证明的逻辑跳跃。
- C3 的真值与裁决边界由作者的 clause、排除表和 mutation 同时控制，存在循环验证；全做通亦不证明方法有效。

**Major**

- VAmPI `vulnerable=0` 已被官方说明并非完全安全，排除表无法自动转化为 FPR 真值。
- L0 人工 clause 标注的输入、独立性、政策来源和仲裁规则未定义，量化结果不可解释。
- L1 仅有官方教学挑战分子，L4 无 BOLA 真值；“precision 显著提升且 recall 不大幅牺牲”在这些层上没有完整可识别的估计对象。
- 方法对合法共享、管理员、代理和其他关系型授权没有必经的负例；这是 fault 306 明示的主要难例。

**Minor**

- `OwnerFields`、稳定唯一字段、响应规范化、重复次数 k、异步轮询和“同型资源”的具体定义尚未冻结，独立实现会分叉。
- BOLA 与 BFLA、读与写在标题、L1 清单和判定逻辑中仍交织；若只做 BOLA，应把 BFLA 从主评测与动机外推中剥离。
- “同语料”不等于“同任务”：WFD 无 BOLA 标注且许多 SUT 的多账户模型待核实，不能把与 EvoMaster 的 paired 比较预设为公平。

### 六、最强反驳（200 字内）

本文最致命的问题不是基线少，而是把“攻击者读到/改到受害者对象”当成“攻击者本不该有权”。幽灵对象拒绝、自有对象成功和重复稳定只能证明对象存在与行为可重放，不能证明共享、管理员或代理访问违法。fault 306 恰恰说没有访问策略规格便难以自动判定；作者却以代码 span 和 owner 字段替代该规格，未证其等价。VAmPI 孪生与自建 mutation 只验证作者指定的开关和标签。没有独立政策真值及合法跨账户反例，所有漂亮指标都是循环一致性，不是 BOLA oracle 的正确性证据。
