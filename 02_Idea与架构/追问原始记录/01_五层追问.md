# Round 1：五层苏格拉底式追问

以下问题先承认方案最强的钢人化版本：v3 不再声称 LLM 首创，而是试图把 BOLA 从启发式告警推进为带证据、带状态校准、可重复评测的运行时裁决。问题在于，这个更窄的主张是否真的已被当前方案支撑。

## 第 1 轮 · 五层追问

### Layer 1 · PROBLEM FRAMING

1. **[Q:CLARIFY] [Critical]** 在 v3 §2 的 C1 以及 §4.1 的 L0 行中，“决定一个端点访问权所需的授权 clause”究竟以什么可重复的边界切分：一个 ORM 字段、一个 SQL predicate、一个角色条件，还是一条人工解释？若两名标注者对同一端点切出不同数量的 clause，C1 的“规格缺口占比”如何仍是可证伪的量？

2. **[Q:PROBE] [Critical]** v3 §2 仅以 EvoMaster `fault 306` 的自述“没有 formal specification 时难以自动判断”支撑 C1；这是否只证明 EvoMaster 的该 oracle 选择了启发式，而没有证明现实 API 的授权规格普遍无法由现有输入或代码证据表达？如果不能区分这两个命题，C1 是否把工具局限性偷换成问题现实性？

3. **[Q:CLARIFY] [Major]** v3 §2 的 C1 同时声称 clause “无法用 OpenAPI 表达”且“无法被 EvoMaster 类启发式覆盖”。这两个分母、端点集合和“覆盖”的判定单位是否相同？若不相同，如何避免用不同口径拼出一个看似坚实的缺口比例？

### Layer 2 · METHODOLOGY REFLECTION

1. **[Q:PROBE] [Critical]** v2 §3.1–§3.3 与 v3 §2.3 把证据图、`OwnerFields` 和 producer-consumer 状态搭建称为“确定性”，但 v2 §3.2 又允许 LLM 在候选边上选择 clause、在不可满足条件处提供解释候选；当 ORM 归属字段、SQL owner 列、路由参数和运行时对象不一致时，究竟哪个证据具有优先权，谁来裁决冲突？

2. **[Q:PROBE] [Critical]** v2 §3.3 的 `confirmed-read` 条件要求响应中有受害者对象的稳定唯一字段且排除幽灵字段集；若对象字段可公开、响应经过脱敏、分页/缓存/异步导致签名变化，方案如何证明“读到的是受害者对象”而非相同 schema、关联对象或可预测的公共记录？

3. **[Q:CLARIFY] [Major]** v2 §3.3 的 `confirmed-write` 只要求“可回读的受害者对象状态发生改变”。如果写操作本身被业务规则接受、但改变来自并发任务、重试或攻击者自己的别名对象，状态校准如何归因到被测请求？

4. **[Q:PROBE] [Major]** v3 §4.3 把 `likely` 与 `inconclusive` 排除在主指标之外，但 v2 §3.2 又把无法证明的 relation 记为 `unknown`、不得编译为告警；是否存在一种失败分布，使方法通过大量降级为 `likely/inconclusive/unknown` 来保持低误报，却几乎不承担漏报代价？

### Layer 3 · EVIDENCE DESIGN

1. **[Q:STRUCTURE] [Critical]** 针对 v3 §4.1 的 L1 行，crAPI 的官方 challenges 与 VAmPI 的官方缺陷清单分别是“已承认的教学/缺陷集合”，不是穷尽真值；在不把它们当 recall 分母的前提下，L1 的 recall、漏报和“检测能力”究竟如何定义，才能不把“找到了官方列出的项目”写成安全检测有效性？

2. **[Q:STRUCTURE] [Critical]** 针对 v3 §4.1 L2 行及 §4.3 第 2 条，VAmPI `vulnerable=0/1` 是否只切换授权检查，还是也可能保留 debug 等固有缺陷？谁在实验前、依据什么独立标准冻结完整排除清单，且如何防止用被测 oracle 的结果反过来决定哪些端点应排除？

3. **[Q:STRUCTURE] [Critical]** 针对 v3 §4.2 的 EvoMaster baseline 行，若 EvoMaster 306 的输出是“likely should have been protected”的告警，而本方案主指标只计 `confirmed-read/write`，两者究竟比较同一检测任务、同一请求预算和同一真值，还是仅比较两个不同语义的告警集合？若后者，paired 比较的统计解释是什么？

4. **[Q:STRUCTURE] [Major]** 针对 v3 §4.1 L3 行和 §4.3 第 3 条，构造式真值由作者生成、对象映射和 mutation diff 也由作者控制；blind protocol 能隐藏测试顺序，却不能消除作者决定缺陷形态、可观测字段和修复方式带来的谱系偏差。哪些现实失败模式会被该层系统性排除？

5. **[Q:STRUCTURE] [Major]** 针对 v3 §4.1 L4 行，WFD 被明确标为没有 BOLA 真值、只能服务 FPR/触发率/规模；在没有多账户模型核验和真实标注前，作者如何保证 L4 不会通过“触发更多”来暗示更强的 BOLA 检测能力？

### Layer 4 · CRITICAL SELF-EXAMINATION

1. **[Q:CHALLENGE] [Critical]** 针对 v3 §2 的 C1：如果动机实验最终发现 OpenAPI 不可表达的 clause 很少，或 EvoMaster 启发式已覆盖大多数实际可观察案例，作者是否承认“规格缺口是论文基石”的论证失败，而不是把 C1 改成较弱的工具工程观察？

2. **[Q:CHALLENGE] [Critical]** 针对 v3 §2.1、§4.1 L2 和 §4.3 第 2 条：若 VAmPI `vulnerable=0` 仍存在未被预先识别的漏洞，或 secure/vulnerable 两实例并非只差授权检查，作者是否承认核心阴性对照失效，并撤回“直接削弱人为注入攻击”的论断？

3. **[Q:CHALLENGE] [Critical]** 针对 v2 §3.3 的 `confirmed-read/write` 与 v3 §4.4 的“去掉幽灵对象对照”消融：如果去掉幽灵对象后 FPR 没有显著上升，或者加入幽灵对象只增加状态不可达和 `inconclusive`，作者凭什么仍称“自有对象成功签名/幽灵对象拒绝签名”是核心仪器而非昂贵的过滤启发式？

4. **[Q:CHALLENGE] [Major]** 针对 v3 §4.3 第 1 条：预注册“precision 显著提升且 recall 不大幅牺牲”是否在没有预先给出显著性检验、配对单位、效应阈值和样本量时仍是成功标准，还是一条可在结果出来后任意解释的方向性愿望？

5. **[Q:CHALLENGE] [Major]** 针对 v3 §6 的风险表中“唯一还没被占的 oracle 校准与真值构造”这一定位：既然 v3 §2.1 已承认差分、变形测试和对象 ID 交换并非首创，作者如何证明“把它们组合成状态校准 oracle”是可归因的新方法，而不是已有部件在新靶场上的工程整合？

### Layer 5 · SIGNIFICANCE & CONTRIBUTION

1. **[Q:CHALLENGE] [Critical]** 针对 v3 §2 的 C1–C3 及 §5 的论文骨架：若 C1 只能由少量人工 clause 标注支持，C2 只能在 VAmPI 配对孪生上显示静默，C3 只是 version pin 后的协议描述，那么三者是否足以构成 JISA 意义上的方法贡献，而不只是一个基准实现和测试脚本集合？

2. **[Q:CHALLENGE] [Critical]** 针对 v3 §4.2 的 baseline 矩阵：BACFuzz、BolaZ、MOCGuard、ACBreaker、NeO、Udd26 均不能公平运行，BolaRay 也只计划做可行性探测；在主要竞争方法不能复现、唯一可运行对照又语义不等价时，作者如何排除“优势来自比较缺口”而非来自 oracle 本身？

3. **[Q:CHALLENGE] [Critical]** 针对 v3 §2 的表述“把可疑升级为有分级、有证据、可机检裁决”：`likely` 与 `inconclusive` 明确不能计入主指标，`confirmed` 又依赖作者抽取的 `OwnerFields`；这是否只是把不可判定性转移到规格抽取和状态可达性，而没有真正解决 BOLA 的开放世界授权语义问题？

4. **[Q:CHALLENGE] [Major]** 针对 v3 §2.1 的“不声称发现更多漏洞、不声称推断开发者意图”与 §4.3 的 precision/recall 目标：若 oracle 只验证“实现行为是否符合候选契约”，它的实际安全意义是什么？发现一个违反候选 clause 的行为，如何证明这不是合法的跨用户访问或业务例外？

5. **[Q:CHALLENGE] [Major]** 针对 v3 §4.4 的七项消融：如果 LLM 被降级为可选排序器、确定性状态搭建才是关键、而所有真值层又分开报告，论文最终不可替代的核心究竟是哪一个组件，以及为什么该组件值得单独发表？

## Critical 级问题后果

- **Layer 1–Q2**：如果作者答不上来，论文的立论基石会从“真实且普遍的研究缺口”降为“某个工具的自我限制”，动机不足以支撑方法论文。
- **Layer 2–Q1**：如果作者答不上来，所谓确定性证据链没有唯一裁决，核心 oracle 将无法复现或审计。
- **Layer 2–Q2**：如果作者答不上来，`confirmed-read` 可能只是响应相似性启发式，核心判定有效性不成立。
- **Layer 3–Q1**：如果作者答不上来，L1 没有合法 recall 分母，任何检测性能结论都不可解释。
- **Layer 3–Q2**：如果作者答不上来，VAmPI 阴性对照可能被污染，FPR 仪器失效。
- **Layer 3–Q3**：如果作者答不上来，主 baseline 比较不是同任务比较，paired 结果不能支持优越性。
- **Layer 4–Q1**：如果作者答不上来，C1 必须撤回或降格，全文动机链条断裂。
- **Layer 4–Q2**：如果作者答不上来，v3 最自信的“官方安全孪生”论据不成立，且不能再用它反驳人为 benchmark 的质疑。
- **Layer 4–Q3**：如果作者答不上来，核心仪器的必要性未被证明，方法贡献退化为复杂的过滤组合。
- **Layer 5–Q1**：如果作者答不上来，C1–C3 不足以形成超越工程 artifact 的期刊贡献。

- **Layer 5–Q3**：如果作者答不上来，方案没有解决开放世界授权语义，只是把不确定性藏进上游输入和弃权 verdict。

## 你最强的单一反驳

即使 fault 306 只证明工具局限，VAmPI 孪生和分层 verdict 也能证明工程价值；但若无独立真值、共同语义 baseline 与预注册阈值，它仍只能证明“能运行”，不能证明“判得对”。
