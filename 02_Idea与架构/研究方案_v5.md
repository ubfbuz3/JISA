## 1. 核查结论摘要（v5 的事实基础）

### 1.1 MST-wi 是我们必须正面处理的最强相关工作

IEEE TSE 2023，76 条系统无关 MR，Jenkins/Joomla 上 85% 敏感度、99.81% 特异性，**工具与复现包完全公开**（`github.com/MetamorphicSecurityTesting/MST` + Zenodo `10.5281/zenodo.7702754`）。

**它已包含 BOLA 的授权 MR**：
- `MR CWE_15_639_OTG_AUTHZ_004`（**CWE-639 = "Authorization Bypass Through User-Controlled Key"，即 BOLA 的标准 CWE 定义**）
- `MR CWE_266_267_268_269_285_522_529_862_863_OTG_AUTHZ_002`
- 其做法：换凭证执行同一输入序列、替换参数为他人的值 → 期望 `isError ∨ 输出不同`

### 1.2 它的例外处理只有两个谓词

从 129 页 MR 目录提取的 DSL 谓词全集：

| 类别 | 谓词 |
|---|---|
| 主体属性 | `isAdmin(user)`、`isLogin`、`afterLogin`、`notAvailableWithoutLoggingIn` |
| **主体间关系** | `isSupervisorOf(user1, user2)` |
| GUI 可达性 | `cannotReachThroughGUI(user, url)`、`notTried(user, url)` |
| 输出 | `isError`、`different`、`equal`、`userCanRetrieveContent` |

**对象级谓词零命中**：`ACL`、`belongsTo`、`canAccess`、`hasAccess`、`granted`、`owner`、`ownership` 全部未出现。

### 1.3 论文自身从未讨论这个限制（已逐词核实 43 页全文）

- Section 11 (Threats to Validity) 只讨论标注一致性（Kappa 0.707）、统计方法、构念效度
- 全文 `owner` / `ownership` / `delegat` 命中 **0** 次
- 作者的应对方式（原文）：**"to avoid false alarms, the user ... should not be a supervisor with access to all the resources of the other user"** —— 即**用主体关系谓词把已知合法角色过滤掉**
- specificity 的**分母是 follow-up 输入数**，且实验对象 Jenkins/Joomla **没有对象级共享语义**

> **结论**：MST-wi 处理的例外类，恰好是它语言能表达的那两类。这不是疏漏，而是**语言表达力决定的边界**。

## 2. 核心机制：例外表达力层级

### 2.1 三层例外（BOLA 的合法跨账户访问）

| 层级 | 形式 | 含义 | 元数 | MR 语言可表达？ |
|---|---|---|---|---|
| **E1 主体属性** | `f(i)` | 管理员 / 运营角色 | 1（主体） | ✅ `!isAdmin(i)` |
| **E2 主体间关系** | `g(i, u_A)` | 上级-下属 / 同组织 | 2（主体，主体） | ✅ `!isSupervisorOf(i, u_A)` |
| **E3 主体×对象显式授权** | `h(i, o)` | **对象级 ACL / 共享 / 委派** | 2（主体，**对象**） | ❌ **原理上不可表达** |

### 2.2 不可表达性论断（E3 为什么表达不出来）

**命题**：在 MR 框架内，E3 类例外条件无法被表达，除非退化为重言式。

**论证**：
1. 判定 `h(i, o)` 为真，意味着确定"`i` 是否被显式授权访问对象 `o`"；
2. 而"`i` 是否被授权访问 `o` 的读操作"，正是 `P(i, o, read)` —— **BOLA 判定所要确定的政策谓词本身**；
3. 故 `h(i, o) ≡ P(i, o, read)`；
4. 若把 `h` 作为 precondition 加入 MR，MR 形如 `¬P(i, o) ∧ … → 应当拒绝访问`，即"**若 `i` 无权访问，则 `i` 无权访问**"——重言式，检出力为零；
5. 故 E3 在 MR 范式内原理上不可表达。∎

> **这个命题的可证伪性**：如果能给出一个出现在现有 MR 目录中的、能表达 E3 的谓词——命题即被推翻。核查已穷举其谓词全集，未发现。（`userCanRetrieveContent(u, output)` 看似相关，但它判定的是**运行时实际取到了什么**，而非**政策是否授权**，因此不构成例外表达。）

### 2.3 从表达力到辨识力（这就是"可判定边界"）

**定义（辨识力）**：MR `R` 对应用 `A` 具有辨识力 ⟺ 对 `A` 上每个 `R` 触发的观测 `O`，都不存在与 `O` 一致的合法例外假设。

**判据（可机检）**：
```
输入：MR R，应用 A，触发观测 O（涉及主体 i、对象 o）
────────────────────────────────────────────
1. 若 R 的条件语言含排除 E1 的谓词，且不存在 E1 型例外
      → 辨识力保持
2. 若 R 的条件语言含排除 E2 的谓词，且不存在 E2 型例外
      → 辨识力保持
3. 若 A 的资源存在 E3 型授权（对象 o 曾被显式共享）
      → R 语言无法排除；若 O 与"合法共享"假设一致
      → 辨识力丧失 → 输出 indeterminate（附见证：共享操作记录）
4. 否则 → violation-proven
────────────────────────────────────────────
```

**关键区别（与 v4 的弃权对比）**：

| | v4 的弃权 | **v5 的弃权** |
|---|---|---|
| 依据 | "证据不足"（主观） | **E3 例外的存在性**（客观、可枚举） |
| 见证 | 抽象的 `W₁/W₂` 政策假设 | **具体的共享操作记录**（我们主动创建时目睹） |
| 可复核 | 需重新推理 | 查共享记录即可 |

> **这是"可判定边界"的可执行形式**：边界不是经验阈值，而是**"该 MR 的例外语言能否覆盖该应用实际存在的例外类"**。

### 2.4 修正方案：Boundary-Aware MR Execution

不要停在"批判"，给出可执行的方法改进——**给 MR 触发加一个 E3 探测步骤**：

| 步骤 | 内容 |
|---|---|
| 1 | 执行 MR，若未触发 → 判定通过 |
| 2 | 若触发 → **探测 E3**：该对象自创建以来是否被显式共享/委派？（由测试框架主动执行的共享操作记录回答，**构造式证据，非政策推断**） |
| 3 | E3 存在 → 降级 `indeterminate`，输出见证；E3 不存在 → 升级 `violation-proven` |

**E3 探测为什么可行且不循环**：我们**主动创建**共享（调用共享 API），因此"该对象被共享给谁"是**我们亲眼产生的构造式真值**——不是从实现制品推断的政策。这正是 v4 想立但当时无法形式化的那一步。

**实测预期（这是论文最有说服力的一张表）**：

| 场景 | MR 触发 | 真实情况 | 原 MR 判定 | **Boundary-aware 判定** |
|---|---|---|---|---|
| 无共享 + 正常 | 否 | 正常 | TN ✅ | TN ✅ |
| 无共享 + 越权 | 是 | BOLA | TP ✅ | `violation-proven` ✅ |
| **有共享 + 正常** | **是** | **正常** | **FP ❌** | **`indeterminate` ✅** |
| 有共享 + 越权 | 是 | BOLA | TP ⚠️（与上一行不可区分） | **`indeterminate`（诚实）或 `violation-proven`（若 E3 被排除）** |

| # | Claim | 可证伪方式 | 证据来源 |
|---|---|---|---|
| **C1** | **表达力层级**：BOLA 的合法例外可分为三层；现有 MR 目录（以 MST-wi 76 条为对象）只覆盖 E1/E2，不覆盖 E3 | 若能指出目录中任一可表达 E3 的谓词 → C1 被推翻 | §1.2 的谓词全集穷举（**已有证据**） |

## 4. 实验设计（v5）

### 4.1 实验对象与工具

| 项 | 内容 | 可得性 |
|---|---|---|
| 被测 MR | **MST-wi 的授权类 MR**（CWE_639 / CWE_286 / CWE_863 族） | ✅ 工具公开，Maven 构建 |
| MR 引擎 | MST-wi（`MST-1.0.0-jar-with-dependencies.jar`） | ✅ 已实测可达 |
| 目标系统 | ① 自建最小 API（含可控的 E3 共享语义）② 现成靶场（VAmPI / crAPI） | 自建 + 公开 |
| 对照 | 同一条 MR 在**无共享**与**有共享**两个版本上的表现 | 构造式 |

**⚠️ 已核实的坑**：**crAPI 没有对象级共享功能**（官方 challenges 只有"访问他人车辆/报告"）。所以 E3 场景**必须自建**——这也是必需的，因为我们需要**主动创建共享**以获得构造式真值。

### 4.2 受控实验：E3 场景下的辨识力

**最小系统设计**（两个变体，端点、schema、OpenAPI 完全一致）：

| 变体 | 资源访问 | 共享端点 |
|---|---|---|
| **V-noE3** | `GET /doc/{id}`，仅有归属 | 无 |
| **V-E3** | 同上 | `POST /doc/{id}/share`（A 可显式共享给 B） |

**四种场景 × 每条 MR**：

| 场景 | 设置 | 真值 |
|---|---|---|
| S1 | 无共享，B 访问自己的 doc | 正常 |
| **S2** | 无共享，B 访问 A 的 doc | **BOLA** |
| **S3** | A **显式共享** doc 给 B，B 访问 | **正常** |
| **S4** | A 共享 doc1 给 B，B 访问**未共享**的 doc2 | **BOLA** |

**核心度量**：

| 指标 | 定义 |
|---|---|
| `FP_E3` | S3 上 MR 触发的比例（**预期显著 > 0**） |
| `辨析力丧失率` | S3 与 S4 观测不可区分（响应等价）的比例 |
| `基线 FP` | V-noE3 上的触发率（对照） |
| `恢复率` | Boundary-aware 执行后，S3 被判 `indeterminate`、S4 被判 `violation-proven` 的比例 |

### 4.3 第二个实验：复现 specificity 口径

复现 MST-wi 的 specificity 度量方式（分母 = follow-up 输入数），在 V-noE3 与 V-E3 上分别报告，**用以说明该指标为何掩盖了本次发现的失效模式**。这不是质疑其原始结果（在其语料上成立），而是**指出指标的可迁移性边界**。

### 4.4 预注册成功标准

1. **C1 的证据完整**：谓词全集穷举 + 76 条 MR 条件逐条核对（已部分完成）；
2. **C3 的方向性**：`FP_E3` 显著高于 `基线 FP`（方向不符则如实报告 C3 被证伪）；
3. **辨析力丧失率可观测**：S3/S4 存在响应等价的触发实例；
4. **Boundary-aware 的收益与代价**：报告恢复率，**以及把真正 BOLA 误降为 `indeterminate` 的比例**（代价必须诚实报告）；
5. **每个判定附证据**：MR 触发记录 + 共享操作记录 + 三组对照响应；
6. **全部代码与场景可重跑**（含 V-noE3 / V-E3 的 compose 与 version pin）。

### 4.5 消融

| # | 消融 | 回答什么 |
|---|---|---|
| 1 | 去掉 E3 探测（= 原始 MR 行为） | 边界修正的净收益 |
| 2 | E3 探测退化为"凡触发即降级" | 说明探测是**对象级**而非"一律弃权"（否则等于放弃检测） |
| 3 | 只加 E1/E2 过滤（复现 MST-wi 做法） | 证明现有例外处理不足以覆盖 E3 |
| 4 | 换 MR 引擎实现（自实现最小版） | 结论不依赖特定实现 |
