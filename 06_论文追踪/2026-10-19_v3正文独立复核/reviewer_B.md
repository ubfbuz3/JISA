### RB-M1

**Severity** Major  
**Blocking** No  
**Axis** 实验设计、统计口径、证据与结论一致性  
**Claim pointer** `03_论文撰写/paper/sections/03_protocol.tex` 第 46 至 49 行将 `direct_only` 定义为不消费访问结果。`sections/04_synthetic.tex` 第 89 至 97 行据此解释不公平对照，第 153 至 158 行却称覆盖率表仅对同一批记录改用 decision 评分。  
**Evidence pointer** `04_绘图与分析/analysis/compute_all.py` 第 523 至 534 行分别执行 `direct_only = st == none` 和 `direct_observe = st == none AND obs200`；`analysis/ingest_coverage.py` 第 113 至 123 行则先定义后一条规则，再把它同时用于两种方法。`results/numbers.tex` 第 321 至 327 行给出 direct_only 的 108 个 TP、108 个 FP；`results/coverage_table.tex` 中同名方法却为零 false proofs、零 misses、零 risk。原始基础是 `experiments/results/raw_matrix.jsonl` 与 `ablation_direct.json`。

**Concern** 这不是弃权分母改变产生的差异。覆盖率生成器给 `direct_only` 额外加上访问成功条件，使它与 `direct_observe` 完全相同。独立重算原先声明的 `direct_only`，可读的 312 条中有 108 条真实违规报警、108 条正常但正确拒绝的请求报警、96 条正常不报警，另有 264 条不可读弃权。其二值违规标签下的误报风险为 108/312，即 34.62%，而不是零。

这里还有需要一起澄清的术语问题。上述 108 个错误报警全部为 E=deny、Y=deny，并非 E=allow 的合法成功访问。`experiments/real_system/entitlement.py` 第 225 至 269 行对这类情况给出的类别是 `alarm_on_denied_not_exploitable`，不算严格 false proof；真实系统段 `sections/05_realsystem.tex` 第 125 至 130 行也遵循该严格含义。因此不能把构造表中“对非违规记录报警”的 FP、严格 false proof 和覆盖率表的错误风险当成同一个数。

**Implication** 公平对照 `direct_observe`、v3 和三条配对差异不受这个错误直接影响，故不认定为中心结论的阻断项。但它使弃权与风险这一明确审稿要求的答复不准确，也违背全文强调的变量和真值分离。

**Resolution test** 让所有表调用同一个方法判定函数。保留不消费 Y 的 `direct_only` 时，覆盖率重新评分必须保留其 108 个错误的漏洞报警，并按统一定义报告错误风险；若严格 false proof 仅允许 E=allow，则另外列出这 108 个无违规效果的无效主张，不能通过给方法加入 Y 条件消除它们。逐条回归核对两个表的判定一致，只有弃权处理和分母可以不同，修正正文、表注和回复信中受影响解释。

**Concern** 关键数字并非全部由已归档实验记录确定。原生运行时“仅改一个构建文件、零 Java 改动”的宏来自复算当天另一仓库的状态，外部仓库以后新增文件或改动也能改变历史实验的描述。隔离重算中 14 个步骤虽都退出成功，`metrics.json`、`numbers.tex`、`native_engine_numbers.tex` 仍有差异，具体为源码派生 F6 项缺失以及三个改动数变为破折号。本评审环境允许读所需源码，但拒绝 Git 进入该外部仓库，故这部分差异不能被解释成作者原始数字错误；它暴露的是生成器把不可访问的外部实时状态当成静默缺值，仍返回成功。

另在隔离副本仅把首条记录的 `http_requests` 加一，`ingest_coverage.py` 正常退出并生成变动成本。原始仓库未改动，测试后已恢复隔离输入。这不表示清单校验无效，而说明“生成器自己会拒绝修改输入”和“用户另外运行 verify 模式可发现修改”是不同合同，目前正文没有区分。

**Implication** 本次已重算成功的时序、分层、配对和缺陷门结果仍成立。问题在于不能据此宣称一个陌生机器上的完整冻结制品已经全部字节复现，也不能用当前 Git 工作区状态证明历史运行时的代码改动面。这是对原审稿可复现性要求的重要剩余缺口。

**Resolution test** 将实验时的上游 commit、源码摘要、精确补丁和改动清单冻结为版本化输入，用它们生成历史事实，实时 Git 状态只能作为附加诊断。把外部源码路径参数化并给出固定版本的获取及构建命令。让一键复算在处理数据前校验输入摘要，缺少承重来源时明确非零退出。更新过时的制品说明，在全新路径的隔离检出中删除既有生成物再完整生成及比对；如只做到同机器重算，正文和回复信应如实限定。
