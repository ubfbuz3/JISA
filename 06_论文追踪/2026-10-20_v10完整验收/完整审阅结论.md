## 二、投稿前应修正的定点问题

### 1. Table 17 把“不具独立性准入资格”写成了“不健全”

位置：`04_绘图与分析/analysis/ingest_multiclass.py:185`，正文 p.18 Table 17 caption。

原句是：`target's oracle being sound, which it is not for any class under the admission rule ...`。

这句话表示 oracle 在所有类别都不 sound，与本表 9/9 对已知真值的正确裁决及零假警相冲突。登记册给出的实际结果是没有任何一类被 **admit as independent**，不能据此推导它们实际回答错误。

建议替换为：`The oracle is sound on these recorded cases, but is not admitted as an independent entitlement source for any class under the admission rule ...`。

同时 `05_realsystem.tex:557` 的总括 `shares the decision function` 不准确覆盖 C2/C4。可改为“shares authorization state or decision components, with the grounds differing by class”，与 VI-E 的分类解释保持一致。修生成器后再生成表，不手改表文件。

### 2. 留一法对四类的关系归因被说过头了

位置：`05_realsystem.tex:562–566`；`response_to_reviewers.tex:552–556`。

当前两处都声称四类均在 relation 和 channel-matched adjudicator 上通过“关掉该类便消除该类告警”的归因。源码 `_any_alarm()` 实际取三种方法的 OR，包含 `direct_observe_channel`；因此复合指标的四类归因有效，不能推出每个组成方法都有四类归因。

| 类别 | 读关系开启→关闭 | 渠道关系开启→关闭 | 渠道直接裁决开启→关闭 |
|---|---|---|---|
| C1 | 3→0 | 3→0 | 3→0 |
| C2 | 0→0 | 2→0 | 2→0 |
| C3 | 0→0 | 0→0 | 2→0 |
| C4 | 0→0 | 0→0 | 2→0 |

应明确：直接裁决或复合指标的归因覆盖四类；读关系仅 C1、渠道关系仅 C1/C2 有“从有告警到无告警”的归因证据；C3/C4 的关系始终不报警。数据、总分母和主要召回数无需改。逐方法证据在 `checks.json` 的 `leave_one_out_by_method`，本次真实运行同样复现。

本次单独包装 `gitea_lab.Client.req()`，按 `_measure()` 的负例代码块统计真实 HTTP 调用，结果见 `negative_cost_trace.json`：
