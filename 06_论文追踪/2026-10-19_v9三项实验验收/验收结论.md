## 必修 1：预算上限不能改变不需要额外请求的原判定

`experiments/run_baseline.py:116`：

```python
if budget_cap is not None and budget_cap < 3:
    ...
    abstained = True
```

这个分支先于原裁决器执行，无论 MR 有没有触发都强制弃权。原裁决器 `experiments/boundary_aware.py:99` 明确规定，MR 未触发时直接返回 pass，且不请求 oracle。

因此 cap=2 的 “42/42 全弃权”测量的是新加的强制弃权策略，而不是原 MR+v3 在预算限制下的行为。应保留原逻辑顺序：

1. MR 未触发，返回 pass，不花额外请求。
2. MR 触发且剩余预算不足，弃权。
3. MR 触发且预算足够，按原方法读 oracle 并裁决。

根据已有 42 格结果，预计应为 15 pass、27 弃权；这两个修正后数值应通过重跑生成，不能由文字手抄替换。cap=3 的主要结果不因本问题必然改变。

`ingest_budget.py:84`、正文 `06_boundaries.tex:421` 及回信另把 111 而非 126 请求解释为 “an abstaining cell costs nothing”。这是错误的：弃权格仍做了 owner/actor 探测，一些格还做了失败或解释性 oracle 查询。真正节省的是 **15 个未触发格不再读取 oracle**。请修生成器的 caption 和对应文字。

## 必修 2：按源码纠正独立性登记册

`R1.4_application_register_run1.md` 的证据不是全部正确：

- **C2 行约 19 行**：写成 PATCH 授权是 `runtime_perm()` 加 bypass。实际 `seeded_target.py:441–457` 的 PATCH 使用 `owner/admin` 条件加 `write_bypass`，并不调用 `runtime_perm()`。
- **C3 行约 20 行**：写 oracle 和内容看到同一个错误继承扩展。实际 oracle 在约 271 行调用 `intended_perm()`；继承错误在约 151–155 行的 `runtime_perm()` 增加 `inherit_perm`。oracle 刻意没有包含这段错误扩展。这也正是实验中 C3 的 oracle 仍能报 none 的原因。
- C4 可以说两条路径共用模型与授权数据，但应明确 runtime 承认污染协作者记录、intended 模型通过 tainted 标记排除它，而不是把二者写成相同的错误授权答案。
- Gogs 被写成 0.13，与正文及归档实验的 0.14.3 不符；主时序实验的 Gitea 1.22.6 也应有可追溯的登记项，不能仅列 1.20.5/1.20.6 后泛称全部主实验版本已登记。

这不意味着这些 oracle 必须改判 admit。应按实际路径区分共享函数、共享状态、同进程保守拒绝，以及无法证明的部分，再依冻结规则填写状态和证据级别。不得用一个正确的保守 reject 掩盖错误的源码理由。

冻结协议头写“at commit cce644d”，但该提交没有协议文件。可证的首次冻结提交为 `a049cb1`，随后 `2c798fc` 固定行尾；这些提交都在预算新结果之前。保留冻结原件及其摘要，通过单独勘误说明澄清元数据/版本笔误，避免事后静默改写事前协议。
