# C · oracle 可容许性：预先冻结的最小协议

**冻结时间：2026-10-19 01:00（+08:00），早于 B 的任何新结果。**
机器可读副本：`experiments/real_system/c_protocol.json`。B 的运行器（`run_temporal.py`）在开跑时读取该文件、把 **sha256 写入运行记录**，并在结束时复核；协议一旦在运行中变动，整轮结果作废。校准单元不计入任何报告分母。

这不是完整的 C 包，只冻结 B 必需的最小规则：E 从哪来、oracle 用谁的凭证、共享缺陷怎么处置、什么时候必须弃权。完整的分渠道验证与校准曲线留到 C 包。

## 1. E（预期授权）只有一个来源：授权台账

E 只由三类记录推导：

1. harness 自己执行的建库/建团队/基线共享事务（每条都有 HTTP 状态）；
2. 带外授权变更事务（每条带 `event_seq` 与 HTTP 状态）；
3. 文档化的继承规则：owner、org owner、site admin、public read、collaborator、org team。

**禁止输入**：任何探针响应（状态码或正文）、oracle 答案 O、观测效果 Y。

- 对象不在台账里，或台账没有覆盖该 (对象, 主体, 动作) 的通道 ⇒ **E = unknown**，绝不落成 deny。
- 变更事务非 2xx ⇒ 台账不更新、`hv` 不递增，该转移的所有格**不进分母**，单列为 failed transition。

已知通道缺口，按实际情况报告而不是吸收：`site_admin` 的读记 allow；`site_admin` 的**写**也记 allow，但三个产品实测不一致（Gogs/GitLab 拒绝），任何 mismatch 单列。deploy key 未建模，只经 deploy key 可达的格必须落 unknown。

## 2. Oracle 用谁的凭证、读什么

- **主视点**：对象拥有者凭证（组织仓库用组织拥有者）。只读 `GET /repos/{o}/{r}/collaborators/{u}/permission`。
- **副视点**：被测主体自己的凭证（黑箱测试者的自然视点），单独记录，不与主视点混算。
- **站点管理员视点不用于 oracle。**

`O` 只是一列交叉核对，**不参与 E，也不参与 TP/FP 判定**。

## 3. 独立性：默认判为 shared，不宣称独立

oracle 读的是产品自己的授权自省面，与 enforcement **同源代码**。该面若有缺陷，O 会被污染。但 E 来自台账，不受其影响，所以分类仍然成立；代价是 **O 不能作为真值**。逐格记 `oracle_independence = "shared"`，不做"独立 oracle"的表述。

## 4. 校准：先测 6 个已知答案，6/6 才开跑

在一个一次性对象上，用同一套 oracle 代码（主视点 + 副视点）测六个已知格：

| 场景 | 视点 | 期望 | Gitea 1.22.6 实测 |
|---|---|---|---|
| 拥有者读自己的私有仓库 | owner | allow | 200，`permission="owner"` |
| 协作者（read）读私有仓库 | owner | allow | 200，`permission="read"` |
| 非协作者读私有仓库 | owner | deny | 200，`permission="none"` |
| 拥有者读自己 | self | allow | 200，`permission="owner"` |
| 协作者读自己 | self | **unreadable** | **403** |
| 非协作者读自己 | self | **unreadable** | **404** |

任一条不符 ⇒ **中止，不产生正式格**。校准格不进分母。

**副视点的结论（写进论文，不粉饰）**：主体自己的凭证读不到这个自省面——read 协作者拿到 403、外人拿到 404。因此自视点**既不能确认也不能否认**，只能作为诊断列记录，不能当 oracle。这与"M2 视点可读性"的旧结论一致，但现在是逐格、有时序的实测。

匿名读没有 oracle 视点（权限端点要求凭证），因此匿名格只按 E 与 Y 计分，`oracle_answer = unknown`。

> 注：本节的 `unreadable` 期望是在**看到任何 B 正式结果之前**由校准运行得到的语义事实（Gitea 的路由/权限行为），不是从结果反推的调参。

## 5. 版本：`hv` 是 harness 的逻辑版本，不冒充服务器原子版本

`hv` 每成功提交一次授权变更 +1，与 `event_seq / mutation / actor / http_status / committed_at / hv_before / hv_after` 一起记录。

**诚实边界**：`hv` 由 harness 维护，不是服务端导出的原子快照号。它只能给"harness 自己执行并确认提交的变更"排序，不能证明服务器内部状态在两次读取之间未变。

一致性规则：E 在 `hv_e` 计算，Y 在 `hv_y` 观测，只有 `hv_e == hv_y` 且冻结的 M0 摘要未变，该轮才可计分；否则整轮按 `version_mismatch` 或 `snapshot_mutated` 弃权。

## 6. 弃权与重试

| 原因 | 条件 | 作用域 |
|---|---|---|
| `transport_error` | status 0，重试 2 次（间隔 250 ms）后仍 0 | 单格 |
| `oracle_unreadable` | oracle 非 200、permission 为空或 unknown | 仅 O 字段 |
| `snapshot_mutated` | 探针前复核 M0 摘要不一致 | 整轮 |
| `version_mismatch` | 台账求值与效果观测之间 `hv` 变化 | 整轮 |
| `mutation_failed` | 变更事务非 2xx | 整个转移 |
| `restore_failed` | 写探针文件在拥有者删除后仍可读 | 该写格，保留并报告 |

**失败的记录一律保留**，不做无痕筛除。

## 7. 观测量：状态码不算 Y

- 读：`Y = (status == 200) AND sha256(body) == sha256(拥有者读同一路径)`。读 `README.md`（auto_init 生成），避免用仓库元数据（`size`/`updated_at` 会被写探针改动）。
- 写：主体建唯一文件 → 拥有者逐字节复读 → 拥有者删除并复读 404。写探针在**读矩阵与 M1 冻结之后**执行，清理后复核 README 摘要未变。
- 顺序：静止窗口内 oracle 先于探针，逐格记录实际顺序与理由。
- 静止窗口：单线程，无并发写者；每轮用 `W0/W1` 时间戳与 `hv` 夹住。

## 8. 必须分开报的量

1. 旧模型（M0）的假确证 vs recrawl（M1）修好的格数；
2. recrawl 之后**仍然漏掉**的通道（可达但未被列举）vs oracle 不可读；
3. 撤销后旧模型仍认为可达（over-approximation）——只要 enforcement 拒绝，**不是真实违规、不算漏检**；
4. 真实违规（E=deny ∧ Y=allow ∧ 报警）与失败转移。

不报 sensitivity/specificity，不把格数外推为部署发生率，不宣称 recrawl 能修好全部不可见通道。
