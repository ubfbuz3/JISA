# B · 真时序实验：结果与边界（Gitea）

**运行：** `20261019_010638`，耗时 344 s，Gitea 1.22.6（`gitea.exe` sha256 `8ad9571723ffb703…`）。
**产物：** `experiments/real_system/results/temporal/temporal_gitea.json`（488 KB）、逐轮 `M0_*.json` / `M1_*.json`、`results/temporal_run.log`。
**先冻结的协议：** `experiments/real_system/c_protocol.json`（sha256 `d09d904707aaf8e0…`），运行记录里保存了同一摘要；协议在结果产生前写定，校准 6/6 后才开跑。

这不是重命名旧 48 格数据。旧实验是**两个快照**；本实验每一轮都提交一次真实授权事务，再以**同一主体凭证**重新采集，并把判定真值锚定在**判定时刻**的台账上。

## 1. 流程与可核验点

每轮闭环：

`crawl（全部主体）→ 冻结 M0（写盘 + sha256）→ 授权事务（2xx 才 hv+1）→ 同权限 recrawl M1 → owner 视点 oracle → 请求 + 内容复读 Y → 按 hv_e 的台账判定`

- 8/8 事务成功（204/200），`hv` 0→8；失败事务不更新台账的规则本轮未被触发（0 失败）。
- 8/8 的 M0 摘要在探针前复核未变；8/8 轮 `hv_e == hv_y`。
- 逐格保存 `run_id/case_id/system_version/subject/object/action/event_seq/timestamp/M0_hash/M1_hash/E/basis/O/vantage/Y/A/H/T/abstain_reason/policy_version`。
- **`hv` 是 harness 逻辑版本**，不是服务端原子快照；单线程、无并发写者，这是"静止窗口"成立的实际条件。

## 2. 结果

8 个转移，7 个对象，5 个用户 + 匿名，共 **280 个换凭证格**：

| 转移 | hv | 格 | 陈旧假确证 | recrawl 修好 | 仍漏 | 陈旧高估（撤销侧） | live 假确证 |
|---|---:|---:|---:|---:|---:|---:|---:|
| 直接授权 | 0→1 | 35 | 1 | 1 | 0 | 0 | 0 |
| 直接撤销 | 1→2 | 35 | 0 | 0 | 0 | 1 | 0 |
| 团队挂载仓库 | 2→3 | 35 | 1 | 1 | 0 | 0 | 0 |
| 移除团队成员（保留直授） | 3→4 | 35 | 0 | 0 | 0 | 1 | 0 |
| 私有→公开 | 4→5 | 35 | 5 | 5 | 0 | 0 | 0 |
| 公开→私有 | 5→6 | 35 | 0 | 0 | 0 | 5 | 0 |
| 角色 read→write | 6→7 | 35 | 0 | 0 | 0 | 0 | 0 |
| 站点管理员授予 | 7→8 | 35 | 6 | 6 | 0 | 0 | 0 |
| **合计** | **8** | **280** | **13** | **13** | **0** | **7** | **0** |

- **E == Y：280/280**，0 个 unknown，0 个弃权格。
- **真实违规（E=deny ∧ Y=allow ∧ 报警）：0**。系统在被测面上是正确的。
- **陈旧假确证 13 个**：直接授权 1、团队继承 1、私有→公开 5、站点管理员 6。全部由同权限 recrawl 修好（13/13），本拓扑上仍漏 0。
- **撤销侧的 7 个"陈旧高估"不是漏检**：旧模型仍列出已撤销的资源，但请求被拒（Y=deny）。按定义，漏检要求 E=deny ∧ Y=allow；这 7 格不满足。
- **多通道**：移除 bob 的团队成员身份后，`acme/t1` 仍经直接协作者可读（E=allow，M0/M1 均可达），`acme/t2` 变为 deny（M0 可达、M1 不可达）。撤销一条通道不等于撤销全部授权。
- **角色变化**：`dave/r2` 上 carol 的读格不变；写探针在变更前 403 且内容未变，变更后 201 且拥有者复读到新字节，随后删除并复读 404，README 摘要清理前后一致。
- **自省面视点**：owner 视点可答 **224/280**（其余 56 格为匿名，无 oracle 凭证）；**主体自身视点只答 7/280**，且这 7 格全部发生在 erin 被授予站点管理员之后。read 协作者自视点 403、外人 404 ⇒ 自视点既不能确认也不能否认，不能充当 oracle。owner 视点可读，但与 enforcement 同源，`oracle_independence = shared`，只作交叉核对。

## 4. 不能写成什么

1. 不能写"recrawl 解决了不可见通道问题"。本实验只说明：**在本拓扑中，时间陈旧造成的漏列可以被同权限 recrawl 修复**；残留为 0 是计数，不是完备性证明。
2. 不能写"旧模型漏检 7 个撤销格"。撤销后请求被拒，没有真实违规。
3. 不能写"13 个假确证是部署中的发生率"。8 个转移是设计集，分母是每轮 35 个换凭证格。
4. 不能写"oracle 独立"。自省面与 enforcement 同源，O 只作交叉核对。
5. 不能把 `hv` 说成服务器原子版本。

## 6. 还没做

- **Gogs / GitLab 复核**：相同语义的关键转移（直接授权/撤销、继承、可见性）尚未在这两个产品上跑。Gogs 没有 `/permission` 后缀，GitLab 的 `members/all` 语义不同，oracle 列需要按产品分别标 unknown 或换端点；这本身是 C 的分渠道结论，不能用一个产品的 oracle 规则套过去。
- **并发更新**：本实验是受控静止窗口；请求与判定之间发生变更的情形尚未测，按协议应另设 schedule。
- **写入的撤销侧**：本轮只测了 read→write 的角色变化；write 权限的撤销（write→read）未单独做转移。
